# 0.47.2 — release report (APPROVED)

One fix on 0.47.1, cut on `release/0.47.x`: `list_dir` with a glob walks on
the search worker. It found the owner's own byte trace: a glob from a home
directory held kiso for 11 s. Each change merged into `release/0.47.x`
through its own PR with `check` and `windows` green; this release adds
only the version bump. The owner approved the round on 2026-10-08 ("when it
is ready, publish 0.47.2"). This session runs the round, and the
Task/Inbox session reviews it independently.

- **Candidate:** 17 tarballs packed from the release branch's head (every
  `dist` deleted and rebuilt first), installed isolated. The release
  smoke and the kill -9 demo ran on them.
- **Lockstep:** a fix → a PATCH under 0.x; 17 packages.
- **Kernel:** 2,192 / 2,200 lines, unchanged.

## What is in it

| PR | what changed |
|---|---|
| #279 | **`list_dir`'s glob walk runs on the search worker.** The owner recorded a byte trace (`KISO_TRACE_BYTES`): during a run, `list_dir` with a glob from a home directory walked synchronously on the main thread for 11.02 s. kiso wrote nothing in that window (no frame, no timer tick), esc did not reach it, and the working row's mark stood still. The walk is still `walkCorpus`, now on the thread `search_text` moved to in CX-1 F4, under its budget: a cap on the files visited (`searchMaxFiles`, 20,000), the deadline (`searchMaxMs`, 10 s) and the abort. Each stop is said as itself (`the walk stopped after N files — narrow the path`, `the walk stopped — its budget elapsed …`), and an abort returns `list_dir aborted`. Both roots are realpath'd first: under a symlinked workspace (macOS `/var`), every listed path used to read `../../…` |
| #280 | #279's comments and test fixture quoted the owner's glob, which named a private product. The candidate's scan found it in two dist files, before the publish, and it is removed. Two timing cases build smaller trees |

## Findings

- **0472-F1 — #279's commit body names a private product.** The merged
  commit `f57eb3da` on `release/0.47.x` quotes the glob in its body. The
  source, the tests, the packages and the PR description are clean. The
  owner ruled on 2026-10-08 not to rewrite the published history.
- **0472-F2 — under its new budget, the glob walk starved a shallow file
  (found after the publish, 2026-10-09).** The owner asked kiso to edit a
  file on their Desktop. `list_dir`'s glob walked depth-first in readdir
  order, and `Desktop/devv/` sorts before `Desktop/generations.ts`. The
  walk spent the 20,000-file budget inside `devv` and stopped before the
  file one level up; 0.47.1, with no budget, found it. The release tests
  and the independent review both used trees far below the budget: a test
  gap and a review gap. Fixed in 0.48.0 (#291): both walkers go
  breadth-first, files before subdirectories. A replay of 292 archived
  bench calls is byte-identical (kiso-doc
  `plan-walk-order-0474-2026-10-09.md`).

### The agent's pass (published 0.47.2, a real model)

The global install of the published 0.47.2 (17 packages, every one read
back at 0.47.2), profile `ds`, the DeepSeek key injected into the one

  `(no match for **/*zz-nomatch*)` and `… the walk stopped after 20000

  `201 lines · 0.0s` (the 200-entry cap and its note). esc, pressed 1.5 s
  after the prompt while the model was thinking, ended the run 25 ms
  later: `stopped by you after 2s · … · everything up to here is saved`.
- On this tree the walk ends in 0.1 s, so esc did not land mid-walk; the
  abort inside a walk is the unit gate's (`list_dir aborted`). The
  owner's checklist repeats the home-directory walk on the real disk.

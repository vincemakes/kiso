# 0.45.3 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.45.3 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.45.3
kiso --version        # 0.45.3
```

## A. Everything in the 0.45.0 checklist

`bench/rd1/0.45.0-dogfood-checklist.md`, on 0.45.3 (`/status` ends with
`version 0.45.3`).

## B. The one change: what an approval policy is handed

#184 (F3) changes what a HOST's approval policy receives, not what the
terminal shows: the terminal's own prompts read the event stream, which
did not move. So in `default` mode:

- Ask for something that needs approval (a `write_file`, then a
  `shell` command). Each prompt appears once; approve one and deny the
  other: the approved call runs, the denied one does not, and the
  verdict line under each reads as it did on 0.45.2.
- Choose "always allow" for a tool, then let the model call it again:
  it runs without a prompt, as on 0.45.2.
- Optional: quit (or `kill -9`) while a prompt is open, then
  `kiso resume`: the prompt is presented again, once.

## C. What would be a finding

- A prompt shown twice, or not at all, for a call that needs approval.
- A remembered allow that stops applying, or applies to the wrong tool.
- Anything in the 0.45.0 checklist that behaves differently on 0.45.3.

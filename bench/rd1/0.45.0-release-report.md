### Steer (ADR-0057), in one paragraph

A person's input arriving while a run is live is **accepted at once and
admitted at a safe point**: every started effect settled, no approval
open, the turn committed. It enters the SAME run as a `user_input` the
model sees on its next request — no second run, no restart, no queue.
An input that arrives after the run decided to end is never dropped: it
is handed back (`SettledRun.unadmitted`, the `unadmitted` frame), and
the terminal sends it as the next turn.

### The GPT adapter, measured

- **#176, prompt cache on the ChatGPT backend** (the providers session's
  live gate, two sessions per arm on the same task):

  | session | requests | requests that hit | fresh input | cached share |
  |---|---|---|---|---|
  | before, 1 | 16 | 11 | 61,857 | 30.2% |
  | before, 2 | 15 | 10 | 52,679 | 32.1% |
  | after, 1 | 17 | 17 | 16,237 | 82.3% |
  | after, 2 | 14 | 13 | 13,119 | 80.9% |

  Fresh input per request falls by about three quarters. Before, the
  hits were almost all the shared static prefix; after, the cached count
  grows with the conversation.
- **#175, reasoning summaries:** with an effort set, the Responses
  stream carries the model's reasoning summary as `thinking`; without
  one, the request is byte-identical to 0.44.0 (a test pins it).

## For hosts

### Action required

- **`estimateTokens` moved** from `@vincemakes/kiso-core` to
  `@vincemakes/kiso-runtime` (ADR-0043 Amendment 13). A host that
  imported it from core imports it from runtime (#172).
- **`session-id` belongs to the adapter on the ChatGPT backend.**
  Requests there now carry `session-id` equal to the prompt cache key
  the host passes (`promptCacheKey`). A `session-id` the host set in its
  own headers is replaced; a host that used that header for its own
  correlation moves the value to another header (#176).

### Observable behaviour changes

- **`SettledRun.unadmitted`** is a new field on what `hooks.onSettled`
  receives: the steers that arrived and were not admitted, `[]` when
  none. A host comparing the whole object sees one more key (#179).
- **A session log may hold `user_input` events inside a run** — between
  a turn's `stop` and the run's `terminal` — once anyone steered it (the
  terminal does, from this release). A consumer that assumed one input
  per run reads each as the person's message at that point (#177).
- **OpenAI Responses, with an effort set:** the stream may carry
  additional `thinking` events holding the reasoning summary. A host
  that renders, persists, replays or counts `thinking` events should
  expect the stream to change. No effort set: no change (#175).
- **Duplicate skill names** resolve to the first occurrence (root order,
  then directory-name order within each root); later ones are reported
  with the broken skills. Only a setup that already held two skills with
  one name sees a difference (#171).

### New optional capabilities (omit them and nothing changes)

- **Steer a live run:** `run.steer(content)` (throws `RunClosedError`
  once the run has decided to end — start a new run with the input),
  `run.retract()`, `run.unadmitted()`. Over HTTP: `POST /:id/steer` →
  202 `{ runId }`, or 409 `idle` / `closed`; an `unadmitted` frame
  follows the terminal when something was left; `client.steer(input)`.
  A host embedding the kernel directly passes `LoopConfig.admit` (#177,
  #179).
- `createAskExtension(ui)`: `ui.ask(spec, signal, ctx)` receives
  `ctx = { sessionId, callId }` (#171).
- `createSkillsExtension({ roots, include })`: `roots` replaces the
  default scan, in order; `include(entry)` filters the one list the
  prompt, `read_skill`, the catalog and the count are built from (#171).
- `createMcpExtension({ servers })`: the `mcpServers` map instead of
  reading `mcp.json`; supplied servers never read or write the tool
  cache (#171).

### Catch-up, this release only (0.40–0.44)

- 0.40.0: retries run on the runtime's budget and are announced through
  `hooks.onRetry` (`{ attempt, maxRetries, code, delayMs, midStream }`).
- 0.41.0: the tool table's vocabulary rows moved to
  `AgentDefinition.toolRules`; a host that passes none gets none.
- 0.44.0: the task extension and `session.assessTasks()` are retired;
  `@vincemakes/kiso-task-ext` receives no further releases.

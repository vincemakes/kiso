## What is in it

| PR | what changed |
|---|---|
| #221 | **The effort is remembered per profile.** `/model <profile> <effort>` (or the panel with a level) records the effort for that profile in `~/.kiso/preferences.json`, and a NEW session of the profile starts at it. A resumed session keeps its own recorded binding, as before. A level the model does not have falls back to the model's default, never to a setting its first request would refuse. When the model has no such level, the effort note now reads "this model's default (it has no X)". The runtime gains `AgentDefinition.reasoning`: a new session's initial reasoning only |
| #223 | **Windows P6: the subagent's wait after a kill is bounded (2 s).** A kill that cannot be confirmed is reported as UNCERTAIN with its pids. An implementer's worktree is kept, and nothing is collected from it. A delegate child that cannot be spawned is reported as `spawn-failed` instead of throwing. The docs state Windows' durability scope and requirements |
| #237 | Test only. The Esc-during-`task_stop` case waits for a settled state; a stop the runner cannot confirm reads `unknown`, never stopped |

## For hosts

### Action required

- None.

### Observable behaviour changes

- **A subagent kill that cannot be confirmed** shows in two places. The
  delegate's result text says "could not confirm the child exited (pid
  …): treat its side effects as UNCERTAIN". The acceptance result (the
  verifier's check or evaluator) carries `unconfirmed: number[]`. An
  implementer's worktree is then kept and not collected. When the kill
  is confirmed, nothing changes (#223).
- **A delegate child that fails to spawn** is reported as a failed
  section, `spawn-failed`, instead of an unhandled error (#223).

### New optional capabilities (omit them and nothing changes)

- **`AgentDefinition.reasoning`:** the initial reasoning of a NEW
  session. A session with a recorded profile ignores it, and
  `setModelBinding` stays the one way to change a live binding (#221).

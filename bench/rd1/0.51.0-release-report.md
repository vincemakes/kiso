# 0.51.0 — release report (APPROVED)

**A model-table release, plus one new SDK seam.** The table knows the 2026-10 models and the effort levels of the
gateways that serve them, a host can choose what a checkpoint records, and two small terminal fixes.

- **Host-defined checkpoint sections** (`contextPolicy.checkpointSections`, ADR-0055 Amendment 3): a static list of
  `{ heading, instruction }` replaces the coding outline in every checkpoint a session writes (the run-start
  summary, the in-run tiers, the manual compact). Every listed heading must appear as its own `## ` line or the
  checkpoint is rejected on the existing route. Absent, the 0.50.1 outline is used byte for byte; the kiso CLI never
  sets the field.
- **The model table:** first-party rows for `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`,
  `gpt-6.1-sol`, `gpt-6-sol` and `gpt-6-luna`; OpenRouter route rows generated from the list (never a default, no
  price); Command Code rows from a live probe, with `none` sent as `off`. A profile can declare its own effort
  levels (`models.<name>.effort`).
- **Headings in the theme gold** (inline code stays blue) and **one decode rate on screen** (the working row no
  longer repeats the status row's `tok/s`).

The first request is **byte-identical** to 0.50.1's.

- **Candidate:** `934333d8`, "chore: release 0.51.0", on main `e5ea4167` (#330); PR #331. The 17 tarballs were
  packed in a fresh worktree after `npm ci`.
- **Lockstep:** a minor (a new public SDK surface: the root goes from 42 to 44 names); 17 packages.
- **Kernel:** unchanged; kiso-core is byte-identical to 0.50.1. Tool schemas and descriptions: byte-identical.

## For hosts

- **Observable:** `contextPolicy.checkpointSections` (new, optional); the root exports `DEFAULT_CHECKPOINT_SECTIONS`
  and the type `CheckpointSection`; the list is validated and copied when an agent or a direct session is
  constructed (an invalid list throws `Invalid contextPolicy.checkpointSections: ...`); model rows gain an optional
  `effort.values`.
- **Passing `DEFAULT_CHECKPOINT_SECTIONS` explicitly** takes the custom path (one added rule and every-section
  validation), not the 0.50.1 default.
- **Action required:** none.

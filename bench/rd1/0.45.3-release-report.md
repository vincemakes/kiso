## For hosts

### Action required

- None for a policy that reads what `PolicyCall` declares.

### Observable behaviour changes

- **An approval policy's first argument is exactly `{ name, input }` on
  every path; the call's id is `ctx.callId` (the second argument) on
  every path.** A policy that read the undeclared `call.callId` saw the
  id on a fresh call and `undefined` after a crash-recovery; it now
  reads `ctx.callId`, which is filled on both. Hooks (`onPreTool`,
  `onPostTool`) are unaffected.

# 0.45.1 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.45.1 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.45.1
kiso --version        # 0.45.1
```

## A. Everything in the 0.45.0 checklist

`bench/rd1/0.45.0-dogfood-checklist.md`, on 0.45.1 (`/status` ends with
`version 0.45.1`).

## B. The one change: usage is reported once per request

#188 changes what the OpenAI-compatible adapter hands a HOST, not what
the terminal shows: kiso's own meter already took the latest report per
request. So on a DeepSeek or gateway session:

- The token line after each turn (`fresh … out …`) reads as it did on
  0.45.0 for the same kind of turn — nothing doubled, nothing missing.

## C. What would be a finding

- A token line that is doubled, zero, or missing after a turn on an
  OpenAI-compatible profile (`ds`, `co`, `op`).
- Anything in the 0.45.0 checklist that behaves differently on 0.45.1.

## What is in it

| PR | what changed |
|---|---|
| #188 | The OpenAI-compatible adapter emits ONE usage event per request. A compat channel may report usage more than once in one stream — two identical usage chunks after the finish, or the cumulative figure on every chunk — and the adapter yielded an event for each, so a host that adds usage events up billed one request two or more times. It now holds the latest (cumulative) report and yields it once, after the stream ends and before the stop; a stream cut off with no finish reason still yields the usage it carried, before the failure. One file; kernel, runtime and CLI 0 |
| #187 | `scripts/demo-kill9.sh` drives today's terminal again (Enter as `\r`, the sessions dir, "rerun it?", `expectedRevision`); assertions unchanged. In no tarball |

## For hosts

### Action required

- None.

### Observable behaviour changes

- **One `usage` event per request from the OpenAI-compatible adapter**,
  just before its `stop` (after any `tool_call_end`), as the Anthropic
  and Responses adapters already did. A host that summed usage events
  per request was over-counting on channels that repeat the usage chunk
  and now counts once; a host that took the last one sees no change.
  Taking the last usage event per request remains the safe rule on any
  adapter.

### New optional capabilities

- None.

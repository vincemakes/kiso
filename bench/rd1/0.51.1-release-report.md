# 0.51.1 — release report (APPROVED)

**A patch for one bug: a session lock left by a killed process with the same pid is taken over, not refused for
ever.** In a container node runs as pid 1. After a SIGKILL (an out-of-memory kill, `docker rm -f`) the lock file kept
`{pid: 1, token: <old>}`; the next container's node is also pid 1, so the lock was read as "another store in this
process", retried 25 times, and refused with "locked by another writer". Every later message on that session
failed, and the session read as poisoned.

- **The fix** (#333): the process keeps the set of tokens its live lock handles hold (on `globalThis`, so a second
  copy of the module shares it). A lock naming this pid is same-process residue only when its token is in the set;
  any other token was left by a previous process and is taken over like a dead holder, through the existing
  rename-away, verify, link path. A live same-process holder is still waited for, and still refused after the
  unchanged retry budget.
- **Not fixed:** a dead holder whose pid is alive in the new pid namespace as an unrelated process (a pid other than
  1). It still reads as alive and is refused; that needs a lease or a boot identity.
- **Test-only change** (#334): the probe cases in `state-probe-lock.test.ts` hold the lock with a `sleep` process
  (they had used the test's own pid as the "live holder", which is the premise of the bug, and a node child's cold
  start passed the 5 s budget under load).

- **Candidate:** `3dbfcbb6`, "chore: release 0.51.1", on main `71a72caa` (#333); PR #334. The 17 tarballs were packed
  in a fresh worktree after `npm ci`; the checksums are in the release notes of the report's kit.
- **Lockstep:** a patch; 17 packages at 0.51.1.
- **Kernel:** unchanged. Protocol, lock file format, tool schemas and the first request: unchanged.

## For hosts

- **Observable:** a lock file naming this process's pid with a token the process did not issue is now taken over
  instead of refused. No new parameter, no format change.
- **Hosts that run one node per container** no longer wedge a session after a SIGKILL.
- **Action required:** none.

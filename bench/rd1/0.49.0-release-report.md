# 0.49.0 — release report (APPROVED)

**Subagents that do not block, and a tool surface that costs less.** A
reader delegation no longer holds the parent for minutes (A, the bounded
join: explorers and reviewers run in the background under a turn budget);
writers run in the background in an isolated workspace and the parent
adopts their patch with one command (B); a child runs on the parent's
model, not the config default (C, with SA-F1's fix: the delegation config
now reaches the subagent extension before it loads); `edit_file` takes
`oldText`/`newText` (#281); the tool descriptions say each fact once
(#293). The first request is **282 tokens smaller** than 0.48.0's.

- **Candidate:** `a7137e75` "chore: release 0.49.0" on `f11807df`, the head

## For hosts

### Action required

- **None for a host that already passes its own delegation config
  through the CLI's path.** A host that built the subagent extension
  itself and read its config at load time should check SA-F1: the config
  must exist before the extension loads.

### Observable behaviour changes

- **`delegate`:** an explorer or reviewer delegation returns at once and
  its result arrives as a task notice; it runs under a turn budget. A
  writer delegation returns a handoff and the patch is adopted with the
  command the handoff prints (`kiso apply-patch`); a writer's turn budget
  defaults to 128 requests.
- **Child model:** a child runs on the conversation's current profile
  unless the task or `subagents.model` names one.
- **`edit_file`:** the parameters are `oldText`/`newText` (plus the
  revision guard).
- **Tool descriptions are shorter**; the first request is 1,114 B / 282
  tokens smaller on the bench's `co` profile.
- **A spent chain budget** is said to the model on a subagent group's end
  too, and to the person once per exhaustion.
- **The unknown-window fallback** is 200K.
- **Packages:** 4 files are new, 35 differ beyond `package.json`, in 8 of
  the 17 packages (kiso-ask-ext, kiso-code, kiso-runtime, kiso-skills-ext,
  kiso-subagent-ext, kiso-tools-node, kiso-tui, kiso-tui-cells); the
  other 9 are byte-identical apart from their `package.json`.

### New optional capabilities

- `onBudgetSpent` on `useTasks` / `TaskDeliveryOptions`.
- Writer delegation and `apply-patch`; `subagents.model` (per role);
  `writerMaxTurns`.

## Findings

- **0490-F1 — T5's median cost is +10.4%** (the expensive side, inside the
  +20% margin, and inside the mini's null band: the 16-pair p95 projection
  is 11.4%). The requests carry 282 fewer tokens at the start, so the
  move is in how the model behaves over the session, not in the prefix.
  "Proposed, for the reviewer." T3 moved the other way (−5.7%).
- **0490-F2 — the reference column's T6 gap is +38.0%** on the mini,
  against +65.9% on the workstation on 2026-10-09 (a move of −28 points).
  The machines differ (the mini's T6 median cost is 192,059 against
  159,659 for the same kiso on the workstation), so this is not a
  like-for-like improvement; the request counts do compare: kiso 90.5 here
  against 96.5 then. BM-1's 15-point rule is met by the move, and the
  record says it was a different machine.
- **0490-F3 — S-chain's control passes now**, because 0.48.0 has the
  chain budget: the test cannot discriminate this release. It still guards
  against a regression of the budget; the kit expected this.
- **0490-F4 — the first full check was red on a test-only matter**
  (above); the moved candidate is byte-identical in its tarballs.
- **0490-F5 — the mini dropped off the network three times** (display sleep
  ten minutes after a remote wake, then the network): twice before the
  freeze and once after the gate. Nothing dropped during the gate; the leader holds the machine
  awake with `caffeinate -dimsu`. Raw legs are archived after the machine
  returns.
- **0490-F6 — the verify re-run rule was not needed** (no verify failure in
  T3, T5 or S-chain); it has not yet been exercised on this machine.

- **0490-F7 — `framing-lock.test.ts` ("THREE real processes race behind
  a barrier: exactly one writer") failed twice on CI in one day** — on
  #301's `check` (zero winners: three `LockedError`s) and on #306's
  `check` (all three lost to a fourth pid) — and passed on the same code
  elsewhere (`f11807df`, `02c5a6da`, the local `npm run check` on
  `a7137e75`, 1,189 PTY tests). The leader re-ran the job. A flaky
  test of a safety property (the single-writer lock), not a product
  failure on the evidence in hand; worth a look at the test's barrier
  under CI load before it costs a release.

- **0490-F8 — two stale lines said only explorers and reviewers run in the
  background** (found by the agent's dogfood: `apps/cli/src/builtin.ts`'s
  comment and the ADR-0058 summary in `docs/adrs/README.md`, although
  writers run in the background since part B). Documentation only. Fixed in
  #309 (the Task/Inbox session): both now read "any role; a writer works in
  its own snapshot and is collected when it ends".

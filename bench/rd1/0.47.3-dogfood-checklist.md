# 0.47.3 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.47.3 is APPROVED.

0.47.3 carries three changes:
- GPT models on the Responses API stop filling every optional tool field
  (#285);
- thinking draws its inline markdown (#286);
- four of kiso's own tools get screen names (#287).

```
npm install -g @vincemakes/kiso-code@0.47.3
kiso --version        # 0.47.3
```

## A. A GPT model edits and runs commands (#285)

1. In a scratch folder, `kiso --model sol` (or your ChatGPT profile).
2. Ask it to change one line of a small file. The `EDIT` card lands on
   its first try: no `pass EITHER search+replace OR edits` refusal.
3. Ask it to run a short command (`git --version`, `ls`). The `SHELL`
   card shows the output inline; it never says `continued as background
   task` for a command that ends at once.

## B. Thinking reads cleanly (#286)

1. On the same GPT profile, with an effort set, ask anything that makes
   it think.
2. A summary title such as `Reading configuration file` is bold inside
   the grey italic, with no `**` around it. While a title streams, its
   `**` may show for a moment, then flip.
3. On `ds`, thinking looks as before.

## C. Tool names (#287)

- A `task_stop` card reads `STOP TASK`, a `delegate` card `SUBAGENTS`, a
  `read_skill` card `READ SKILL`, and an `ask_user` card `ASK USER`. Any
  one of them is enough to check.

## D. What would be a finding

- Any edit refusal that names both forms, or any one-shot command that
  turns into a background task, on a GPT model.
- `**` left on a finished thinking title, or thinking that loses its grey
  italic after a bold span.
- Anything on `ds` that reads differently from 0.47.2, apart from C.

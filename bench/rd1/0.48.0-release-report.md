# 0.48.0 — release report (APPROVED)

**Background work can keep the agent moving.** In 0.47, a task the agent
started while it was answering a wake could end, but its end only
notified: one wake per message of yours (lineage depth 1). 0.48.0 replaces
that guard with a chain budget (ADR-0058 Amendment 9): a task started
inside a wake run wakes the session again, up to 20 autonomous wakes after
one message of yours; past the budget its end notifies ("chain budget
spent"). Two rounds of background subagents now run to the end without
you.

## For hosts

### Action required

- **A host that relied on a task's end waking the session at most once per
  person message** (0.47's lineage depth 1) now gets up to 20 autonomous
  wakes. To keep one: `session.useTasks(manager, { maxWakes: 1 })`, or
  `"maxWakes": 1` in the CLI config.

### Observable behaviour changes

- **Task wakes** chain up to `maxWakes` (default 20) after each person
  input; past it, a task's end notifies ("chain budget spent") and waits
  for your next message.
- **A refused tool call** (an undeclared argument) names that argument in
  its error text (K15a).
- **The shell's foreground wait**, with tasks wired: a `foregroundMs` /
  `timeoutMs` under 60 s is raised to 60 s (no switch; see the new limit).
  Without tasks the wait is a kill timeout and is kept as asked.
- **A task stopped immediately after it starts** now always leaves its
  terminal record.
- **`list_dir` (glob) and `search_text` under their file/time budget**
  return shallow files before deep ones.
- **gpt-6.1-sol on the ChatGPT subscription:** requests carry
  `reasoning: { effort: <the remembered level>, summary: "auto" }`, and
  thinking summaries arrive (0.47.3 sent no `reasoning` field).
- **Traces:** the `rent` ledger gains a `system:tools` row and counts what
  the first request carries; readers of `rent`/`estTokens` see different
  numbers. Request bytes are unchanged.
- **Packages:** 4 of the 17 differ from 0.47.3 beyond `package.json`:
  kiso-core, kiso-runtime, kiso-tools-node, kiso-code (23 files).

### New optional capabilities

- `useTasks(manager, { maxWakes })` and the CLI config `maxWakes`.
- `limits.minForegroundMs` (kiso-tools-node `WorkspaceToolsOptions`):
  the shell's least foreground wait with tasks wired; default 60 s; `0`
  keeps the model's value.

## Findings

- **0480-F1 — S-chain rc3: a model omission, adjudicated.** The second
  wake delivered t4–t6 in full; the model's final turn listed answers 1–3
  only and ended its own turn (265 output tokens). The same class as the
  null's T5 `--count` miss (≈ 1 in 83 legs). The frozen kit kept S-chain's
  verify a hard gate; the owner adjudicated PASSED. Next kit: S-chain gets
  the verify re-run rule too.
- **0480-F2 — T6 runs costlier than the reference on `co`.** +65.9% cost
  tonight, +38.9% last night with a pre-0.48 build (`0.47.4-efr.0`,
  overlapping intervals); kiso's own T6 median cost moved +3.3% between
  the two, the reference's −12.4%. A standing gap on the long session
  (more requests), not a 0.48.0 regression on the evidence in hand; a T6
  rc-vs-control set would settle it. For the roadmap.
- **0480-F3 — T3's median cost +12.3%**, inside the +20% margin with
  byte-identical requests, so behaviour (#290's floor and K15a's text are
  the candidates); T5 +0.25%. "Proposed, for the reviewer."
- **0480-F4 — a pack depends on the worktree's history** (release-flow
  hazard #12): a rebuilt worktree packs the CLI's bin target 0755, a fresh
  one 0644 (every release so far). Every release pack is now fresh.
- **0480-F5 — the gate script's step 5 once no-op'd** (a redirect into a
  root not yet created; it printed done). Caught at the resume; no data
  affected; each step now asserts its artifacts.
- **0480-F6 — the kill -9 demo's phase-2 "marker STILL never appeared"**
  passes trivially (hazard #11); a cleanup, not a blocker.
- **0480-F8 — a delegate child does not follow the parent's `--model`**
  (the dogfood; pre-existing since 0.30.0's DT-1a, not a 0.48.0
  regression). A child gets `--model` only when the delegate call names
  one; otherwise it resolves its model as a fresh CLI would (the config
  default, or the environment). A user who picks a profile with `--model`
  or `/model` gets background children on another model. **Already fixed
  by #295's C1** (task → `subagents.model` → the conversation's current
  binding → the environment), planned for 0.49; whether to cut C1 into a
  0.48.1 is the owner's call. **The key sent to api.openai.com was the
  harness, not kiso:** the first two dogfood launchers exported the
  Command Code key as `OPENAI_API_KEY` (through `cred-exec.sh`) WITHOUT
  `OPENAI_BASE_URL`; kiso reads that pair by design (`apps/cli/src/config.ts`,
  the environment route: the env key at the env URL, OpenAI's default when
  none), so the children — and in run b the parent — sent it to OpenAI
  (refused, 401, the reply masked it). The bench runners always set both;
  the lesson is the harness's: never leave `OPENAI_API_KEY` in a real-model
  run's environment unless `OPENAI_BASE_URL` is set beside it.
- **0480-F9 — the chain budget's own gaps** (found by the dogfood's
  review, confirmed and widened by reading `delivery.ts`): **a subagent
  group's end never carries the "chain budget spent" line** — only the
  single-task path (`#hear`) appends it; `#deliverGroup` turns the wake
  into a notify without a reason, so in the headline case the model is
  not told either; and the person is told nothing on either path (a quiet
  chain looks like an idle one); no test pins the default 20, the "chain budget spent"
  text, `maxWakes: 0`, the reset on a person's message, or the `<`
  boundary. The owner put the follow-up in 0.49 (plan:
  `plan-chain-budget-notice-0490-2026-10-09.md`).
- **0480-F7 — the kit's §10 was stale** (written for `wait`), so the
  standard release-round checks were frozen separately
  (`ruling-0480-smoke`). Kits carry those checks from now on.

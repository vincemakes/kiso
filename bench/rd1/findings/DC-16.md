# DC-16 — removing the id from the picker row removed it from `kiso sessions` too

- **id:** DC-16
- **class:** projection sharing
- **severity:** P2 — the only TTY surface that showed a session id
- **agent:** kiso 0.16.4 working tree (introduced by this round)
- **found by:** an adversarial review checking DC-13's own recorded
  justification against the code
- **status:** FIXED (0.16.4 working tree)

## The measurement

`sessionListRow` — what `kiso sessions` prints on a TTY — is one line:

```ts
export function sessionListRow(card, W, now, idCol) {
    return rowSpans(card, W, now, idCol).text;
}
```

It shares `rowSpans` with the picker. Deleting the id span from
`rowSpans` deleted it from the listing at the same time, silently.

That falsifies two things this round wrote down:

- DC-13's remedy keeps the id as a filter haystack **because** *"`kiso
  sessions` prints ids, and a human who copied one must be able to
  paste it here"*.
- The design amendment says the id *"is still reachable where it is
  USED (`kiso sessions`, `/status`)"*.

Only the **piped** listing (`renderSessionLine`) and `/status` still
show one. The surface a human actually looks at — the CLI's own comment
calls it *"running `kiso sessions` and copying one out by eye"* — showed
none.

## The cause

The module's header states its design: the picker and the listing
"render from ONE definition", so the two can never drift about what a
session IS. That is right and it stays. What it does not license is
treating them as the SAME ROW: the owner's ruling was about the
**picker**, where the id was four characters of machine identity in the
column the eye lands on first. A listing is the opposite surface — it
exists to be read and copied out of.

## The fix

`sessionListRow` appends a dim id after the shared projection, and takes
the tail's width out of the projection's budget so the row still fits.
The picker row is untouched.

A terminal too narrow for both keeps the words: the id is what gives way,
because a row whose title has been cut to nothing identifies nothing.

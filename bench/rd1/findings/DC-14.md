# DC-14 — the ground ladder's rungs 1 and 3 only run when rung 2 answers

- **id:** DC-14
- **class:** wiring / theme resolution
- **severity:** P1 — every terminal that does not answer OSC 11, which
  §3.2 records as the unmeasured majority
- **agent:** kiso 0.16.3 (introduced by DC-3's own wiring)
- **found by:** an adversarial review of the R2 source diff, checking the
  ladder in `ground.ts` against its ONE call site
- **status:** FIXED (0.16.4 working tree)

## The measurement

`resolveGround` is called exactly once in the tree, and it is inside the
OSC-reply callback:

```ts
editor.onOsc((reply) => {
    const next = resolveGround({ theme: …, osc: reply, colorfgbg: … });
```

So on a terminal that never answers `ESC ] 11 ; ? BEL` — tmux does not
forward the reply by default, and many emulators ignore the query —
**no rung is ever consulted**:

- `KISO_THEME=dark kiso` leaves the ground `unknown`. design.md §3
  rung 1 is SETTLED as *"an explicit answer always wins"*; as wired it
  won only when rung 2 also worked.
- `COLORFGBG` — rung 3, which exists precisely FOR the terminals
  without OSC 11 — could only ever be reached when an OSC reply had
  arrived **and been malformed**. Its purpose inverted.

§3.2 records that whether rung 2 fires on real terminals is unmeasured.
That makes this the mainline path, not an edge.

## The cause

DC-3 built the ladder as a pure function and tested it as one:
`ground.test.ts` walks all four rungs and every precedence, and passes.
What it does not test is the WIRING — that something calls it — and the
one caller was written as part of the OSC probe, where the reply is the
subject and the env vars were passed along as arguments rather than as
rungs in their own right.

The general shape: **a pure function with a complete test suite and one
call site is only as correct as its call site**, and the test that would
have caught this is not a unit test of the ladder but an assertion about
startup.

## The fix

Walk the ladder once at startup, before the query and independently of
it; let the reply re-walk it. `theme` goes in first both times, so rung
1 still wins outright and the reply can only upgrade `unknown`.

```ts
setGround(resolveGround({ theme: process.env.KISO_THEME, colorfgbg: process.env.COLORFGBG }));
editor.onOsc((reply) => { … });
```

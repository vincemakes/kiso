# DC-36 — a command whose argument is a closed set must offer the set

**Status**: FIXED
**Reported by**: the owner, asking why switching a tier meant typing
the word `bypass` when a list of five was right there
**Round**: R8b coda, 2026-09-01

## What was wrong

`/mode` printed `mode default` and `tiers: manual default accept-edits
plan bypass`, then stopped. Switching meant typing the tier name —
while bare `/model` has opened a picker since TUI2-R2 ④ and `/resume`
has opened one since TUI2-R2 ②.

Five fixed tiers is the least defensible place in the product to make a
human type: the whole answer was already on screen and only the
choosing was missing — which is word for word the reason TUI2-R2 ④
gave for making `/model` pick.

## The survey, so the rule is not applied one command at a time

Every command, and whether its argument is a set worth offering:

| command | argument | bare, before | verdict |
|---|---|---|---|
| `/model` | a profile name | PICKS (TUI2-R2 ④) | already right |
| `/resume` | a session id | PICKS (TUI2-R2 ②) | already right |
| `/compact` | free instruction text | prints | **no set to offer** — a picker cannot invent one |
| `/mode` | one of five tiers | prints | **the gap** |
| the other seven | none | — | nothing to choose |

So the rule "a command with options offers them" had exactly one
unfinished case.

## The fix

Bare `/mode` opens the pick panel, through the same `panelAsk` +
`PickSpec` path `/model` uses — a second flavour (`modePickView`) is a
name and a fallback question, not a second mechanism.

Each tier carries a note TRANSCRIBED FROM `decide()` rather than
written fresh (`MODE_NOTE`, next to the function it describes): this is
the row a human reads before handing over the approval gate, and a
description that drifts from the behaviour is worse than none.

`/mode <name>` is untouched. Where there is no dock — a pipe, a
dock-less TTY — the printed form survives verbatim, because that is a
machine-readable surface.

## Two things the fix uncovered

**The `t` row had no business on a closed set.** `/model` offers "type
provider/model directly" for a real reason: a list of configured
profiles is never the list of models that exist. The five tiers ARE the
world, so the row carried no fact and cost a line (§1.3). `typeHint` is
optional now rather than removed — the asymmetry is the point — and
with no row to draw, `t` no longer opens a phase either. A key that
leads to a surface the panel does not draw is worse than an absent key.

**The panel's own affordance did not name the arrows.** ↑↓ have walked
this cursor since TUI2-R2 ④ and the keys sheet has said `panels: ↑↓
move` ever since — but the row a human reads WHILE THE PANEL IS UP said
only `digits pick · ⏎ confirms · esc`. That is DC-30's lesson again: a
hint that omits the gesture is why the gesture goes unused, and it is
why the owner read the panel as "type the answer". The row reads `↑↓
move · digits pick · ⏎ confirms · esc` now.

## Two traps hit on the way, both filed here before

- **the non-contiguous needle** (DC-25, DC-29): the pty feed waited on
  `mode — current`, which carries SGR between its words, so it never
  matched the raw stream. The needle is a NOTE now. Third time.
- **a case with no exit feed** blocks the vitest worker until the
  driver's own timeout, and enough of those starve the reporter's RPC

**ROOT CAUSE, found 2026-09-03 and fixed elsewhere.** The starvation is
not about any one scenario being long: vitest's worker answers the
runner over birpc, that reply is a MACROTASK, and `@vitest/runner`
awaits only microtasks between tests — so a file of synchronous
`spawnSync` cases never turns the event loop, and once the FILE's
synchronous total passes birpc's hard-coded 60s the pending reply times
out and vitest exits 1 with every test green. `tests/setup-pty-yield.ts`
yields once per test and settles it. Merging spawns is still good
hygiene — it makes files shorter and suites faster — but it was never
the structural cure: a 40s file on a slower runner is one bad day from
60s.

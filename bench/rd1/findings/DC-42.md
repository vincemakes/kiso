# DC-42 — `⚠` breaks design §6.1 the same way `⏸` did, and nothing said so

- **id:** DC-42
- **class:** glyph budget — a chrome mark the emoji font supplies
- **severity:** P3 — nothing is broken today on Apple Terminal with
  Menlo, because Menlo has `⚠` and wins the resolution. It becomes a
  torn row on any terminal whose font stack falls through to Apple
  Color Emoji for it: the glyph is drawn coloured and double-width on a
  row whose width was computed as one cell (the TUI2-R2pre ① mechanism,
  exactly).
- **agent:** every kiso version. Found 2026-09-02 while retiring `⏸`
  (R9 Q4), by measuring the WHOLE chrome set against the font rather
  than the one glyph under judgment.
- **status:** OPEN, ruling requested. No code moved; the gate that found
  it ships carrying `⚠` as declared debt.

## The measurement

`fontTools` over `/System/Library/Fonts/Apple Color Emoji.ttc` (v1.000,
macOS 26.5.1) and `/System/Library/Fonts/Menlo.ttc`, 2026-09-02:

| glyph | in Menlo | in Apple Color Emoji | §6 verdict |
|---|---|---|---|
| `⏸` U+23F8 | **no** | **yes** | fails both — retired by R9 Q4 |
| `⚠` U+26A0 | yes | **yes** | fails §6.1 |
| `❯` U+276F | yes | no | clean — `⏸`'s replacement |
| `✳` U+2733 | yes | **yes** | §6.1 names it |
| `✴` U+2734 | yes | **yes** | §6.1 names it |

Every other glyph the renderer emits as chrome is clean: `✓ ✗ ✦ ✧ ✶ ✸ ✺
● ▸ ▖ ▣ □ → ─ │ └ █ ▀ ▄`.

So `⚠` is in exactly the company §6.1 bans by name. It is one notch
better than `⏸` — Menlo has it, so the default macOS terminal draws it
narrow and correct — which is why it has never been reported.

## Why nothing caught it

`T-R2p-2` has advertised itself as the §6.1 gate since TUI2-R2pre: "§6.1
forbids any glyph the emoji font could draw double-width, so the ramp is
measured here." It measures `displayWidth`, which is **kiso's own
table**. A glyph that table scores 1 and a terminal draws in 2 is the
precise defect the whole file exists for, and the gate could not see it:
it asked kiso what kiso thought, and agreed with itself.

`⏸` sat inside that green gate for its whole life. design.md §10 wrote
the fact down in prose and no gate ever asked.

R9 Q4 ships the missing half (`T-R2p-4`, with the font coverage pinned
as data in `packages/tui/tests/helpers/emoji-font.ts` so it runs off
macOS too, and `T-R2p-4b` discriminating on `✳ ✴ ⏸`). `⚠` is carried in
`EMOJI_FONT_DEBT` — a declared exception naming this finding, not an
exemption on the merits.

## The eight strings

`⚠` is not decoration; it leads real content, and §1.2 means the words
already carry the fact:

```
approval-panel.ts:217  ⚠ deletes files permanently
approval-panel.ts:224  ⚠ discards your uncommitted changes — unrecoverable
approval-panel.ts:225  ⚠ throws away commits and working changes
approval-panel.ts:233  ⚠ deletes untracked files permanently
strings.ts:133         ⚠ interrupted execution: … — rerun it?
strings.ts:161         ⚠ an unanswered question was interrupted …
tui/render.ts:159      ⚠ <name> failed (<id>): …
cli/chat.ts:689        ⚠ <name> FAILED — the side effect may have applied.
```

## Options for the ruling

- **(a) drop it.** §1.3 is the standing argument: a row that says
  "deletes files permanently" does not also need a mark saying it is
  serious, and the failure rows are already `p.red`. This is the tick
  and the cross retired one more time, and it costs nothing to draw.
- **(b) replace it.** A Menlo-only mark of the same weight — `!` is
  ASCII and survives a pipe; `▲` (U+25B2) is in Menlo and absent from
  the emoji font. Keeps a shape on the danger rows.
- **(c) keep it and amend §6.1** to "absent from Menlo AND present in
  the emoji font", i.e. bless a glyph the default font resolves
  correctly. Honest, and it narrows a rule that was written to be
  conservative.

My lean is **(a)**: the rule §1.3 already decided this class of question,
and the four approval strings are the only ones where a mark could be
argued to add urgency — which is exactly the argument §1.3 rejects.

## Belongs with

R9 Q4 (`⏸` → `❯`, 0.21.0) and design.md §10's first bullet, which that
round deletes. This finding is why the bullet's deletion is not the end
of the subject.

# DC-53 — the cap loop committed a call that was still running, and the work never reached the screen

- **id:** DC-53
- **class:** P1 — committed history written for something that had not
  happened, and a result silently lost
- **severity:** **P1.** A running call's card is frozen into the
  scrollback with its breathing mark, `#committed` steps past it, and
  when the result arrives there is no live cell left to draw it into.
  The call's output never appears at all. The `thinking…` placeholder
  then sits beside a call that is running.
- **agent:** 0.24.0 onward — R13 is what let the loop reach a running
  cell. Found 2026-09-05 from the owner's screenshot, reproduced on the
  real compositor.
- **status:** FIXED in 0.24.4, red before green.

## The measurement

Three parallel searches at 100×24; the second and third settle first.
Their cards are twelve rows each, the live region passes `H − 4`, and
`compositor.ts`'s cap loop commits `#committed` — the FIRST call, still
in flight.

Reproduced directly: before the fix, the transcript contains
`Documents/…` and `Downloads/…` and **no `Desktop/…` at any point**,
though that call settled. The work is not late; it is gone.

## The mechanism

```
while (liveLines.length > cap && this.#committed < this.#cells.length) {
    this.#markSpilled(this.#committed);
    this.#commitCell(this.#committed, W, ctx);   // ← unconditional
```

The loop is not new. **R4's standing activity slot is what kept it away
from a running cell**: the slot held the live region at a constant
height, so the projection never grew past the cap on its own. R13
retired the slot (DC-46), the live region's height became a function of
what is in flight, and this is the first time the loop has reached a
cell that was not done.

The placeholder is the second half. `#thinkingGap()` asked only whether
the turn was in flight; an empty live projection was read as "nothing is
happening". It is also what a wrongly-committed running cell leaves
behind.

## The fix

- **A running TOOL CALL is never force-committed.** The guard is
  specifically that, not "any unfinished cell": a streaming text or raw
  cell HAS a committed form — the rows it has already written are final
  and append-only — and spilling those is what this loop is for. A
  running call does not: its card changes shape at the settle, so a
  committed one is a row that will never be corrected.
- When the head is running and the region is over its cap, the region
  gives way instead, in call order: the cards behind degrade to head
  rows (DC-43's existing ladder in `#liveProjection`), and only if head
  rows alone still overflow is the tail counted — `+N more`. §7.3's
  retired count device comes back for this one case, because a row
  saying how many calls are not shown is the only honest thing left.
- `#thinkingGap()` gains a second condition: any uncommitted cell in
  flight is not a gap.

## The near-miss worth recording

The first cut of the last-resort collapse applied whenever head rows
overflowed the cap, without asking whether the loop was actually
blocked. That TRUNCATED the projection the loop counts its rows from —
so the loop believed the region fit, stopped early, and **lost the rows
it would have committed**: a 40-line burst on a 12-row screen kept 13.
Three existing gates caught it (`tt1-clamp`, `compositor-kc3-at`, the
resize force-commit case), which is what they are for. The collapse now
fires only when the head is a running call, which is the only state in
which the loop cannot act.

## Belongs with

DC-46 (which retired R4's slot and is what exposed this), DC-43 (the
degradation ladder the fix reuses), §7.1 (committed rows are final —
the reason committing a running cell is not merely untidy), and 0.24.2's
`thinking…` placeholder.

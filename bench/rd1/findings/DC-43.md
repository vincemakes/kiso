# DC-43 — D4 makes a turn spill on a 16-row terminal, and the fold then un-scrolls the window

- **id:** DC-43
- **class:** the open spilled-stretch question (design.md §10), given a
  first concrete instance
- **severity:** P3 — nothing is lost and nothing is wrong on screen. The
  rows move: at the turn's end, on a short terminal, the surviving rows
  slide DOWN by as much as the window had scrolled. §7 is protective of
  exactly this ("the screen must not move under the reader"), which is
  why it is written down rather than absorbed.
- **agent:** kiso 0.22.0 (R9 P2 / D4). Found by R7a A2 going red at
  60×16 and 74×16 while staying green at 100×24 and 132×40.
- **status:** OPEN. The gate is amended with a DERIVED bound, not
  loosened to fit — see below.

## What happens

R7a's fixture drives one turn: a thought, a shell, a second thought, a
four-file burst, an answer, the turn's end.

Before D4 a settled shell was one row, and the whole turn fitted a
16-row terminal. D4 gives it five rows of tail plus an outcome row, and
now it does not. The screen scrolls during the burst. Then the turn ends,
the stretch folds, the four read rows collapse to one — and the content
becomes shorter than the screen again, so the window un-scrolls and every
surviving row moves down by three, which is exactly the burst's own
collapse (four reads → one fold row).

```
frame 6 (burst settled, screen scrolled)   frame 7 (turn ends, window un-scrolls)
 0  shell npm run check                     0  why does the CI job fail
 1  └ a                                     1    Short thought.
 …                                          2    shell npm run check
 8  read  package-lock.json …               …
11  read  packages/runtime/package.json …   9    4 × read
                                           10  The lockfile is missing …
```

## What it is NOT

It is not the block-to-fold seam R7a was built for. That seam is R7a E's
case — "the settle changes a row's content, not its position" — and it
is GREEN, because R9 P2 extended R7a's own device to the settled side:
a tool cell is spaced by the one-row stand-in on both sides now, so the
blank `bodySpacing` gives a multi-row cell no longer appears at the
settle. Without that extension D4 would have shifted the head row by one
at every single command completion, which would have been a defect
rather than a spill.

## Why the gate is amended rather than loosened

R7a A2's bound of ONE row still holds at every size where the turn's
content fits, and it is still asserted there. Where the content spills,
the bound is `FILES.length - 1` — the burst's own collapse, read off the
fixture — so the gate still fails if anything shifts by more than the
fold actually removes. A bound fitted to the observed number (3) would
have been a number with no argument behind it.

**The derived bound is a TRANSITIONAL measure, and it has an expiry.**
It exists because the window un-scrolls, and the window is what DC-19's
third decision settles. When that lands in Round 3, the bound returns to
**≤ 1 at every size** — the property R7a A2 was written for — and this
finding closes. That reversion is in Round 3's gate table, so it is a
gate the round must satisfy rather than an intention recorded here.

## The open question this belongs to

design.md §10: *"Spilled stretches. A stretch too tall for its slot
spills; how a spilled stretch folds is not settled."* This is that
question with a measurement attached. The candidate answers are the ones
that question already implies — hold the window when a fold shortens the
content, or reserve the fold's height while the stretch is open — and
both are compositor-scroll decisions, which is the surface R11's route B
(Round 3) rewrites anyway. Deciding it here would be deciding it twice.

## Belongs with

R9 P2 / D4 (0.22.0), R7a A2 and E, and design.md §10's spilled-stretch
bullet, which this finding is the first concrete case of.

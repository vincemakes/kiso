# REL-0152-D20 — kiso paints over the terminal's lines; the reference implementation appends to them

- **id:** REL-0152-D20
- **class:** renderer / how the dock arrives
- **severity:** P2 — destroys the user's on-screen history, and inherits
  the terminal's per-line state
- **status:** MECHANISM ESTABLISHED. The obvious fix was built, measured,
  and NOT taken — it breaks a real invariant. See "Why the fix is not
  here".

## The measurement

Both agents captured in the same PTY, same size (24x80), same startup,
and their escape vocabularies diffed:

| | kiso | the reference implementation |
|---|---|---|
| absolute positioning `ESC[<row>;1H` | **24 — every row** | **0** |
| relative moves | 0 | `ESC[1A`, `ESC[3A` |
| newlines | **3** | **69** |
| line erase | `ESC[0K` x49 | `ESC[2K` x11 |

kiso's first frame goes `ESC[r ESC[?69l … ESC[?7l ESC[?2026h` and then
straight to `ESC[1;1H ESC[0K`, painting row 1 over whatever the terminal
was showing. The other appends below and only ever redraws its last few
rows relatively.

## Why that matters twice

**It destroys the user's terminal history.** What was on screen when
kiso started — the shell prompt, the command that launched it, the tail
of the last thing that ran — is not scrolled away, it is overwritten. It
is gone, not in the scrollback. That is a strange thing for a product
whose claim is that the terminal's scrollback IS the transcript.

**And a terminal's per-line state belongs to the LINE.** macOS Terminal
marks the lines it believes are shell prompts and draws those marks as
brackets. Painting kiso's chrome on top of a marked line leaves the mark
where it was, now decorating a row that has nothing to do with it — and
the mark rides that row as the screen scrolls. That is REL-0152-D1's
symptom, chased for five rounds, and the reference implementation is
immune for the same reason it preserves the history: it never touches
those lines.

The owner's own screenshots close it: their brackets appear around the
SHELL PROMPT under both agents, and around the composer under kiso only.

## Why the fix is not here

Scrolling a screenful away before the first frame is four lines, and it
works. It also pushes up to H BLANK rows into the scrollback, and
TUI2-R2pre's blank-share gate went from 14/43 to 29/43 — past the "a
healthy session's scrollback is mostly content" invariant that gate
exists to hold, and past it in the same direction the finding it guards
was about.

Trading a symptom that has a five-second user-side setting for a broken
invariant is a worse deal than the bug. The gate is right.

The correct version scrolls only as far as the terminal's content
actually reaches, which needs a cursor-position query at boot. That is
its own round with its own risk: this file already declined a boot-time
round-trip once, for racing the editor for stdin.

## What the owner should do now

Terminal.app → Edit → Marks → uncheck "Automatically Mark Prompt Lines".
It marks the shell's own prompt too, so it is not a kiso-specific
setting.

## The lesson

Five rounds went into "which byte of kiso's output makes a bracket". The
answer was that none of them do — kiso's fault was not what it WROTE but
WHERE it wrote it, on lines that already belonged to something else. The
comparison that showed it took one capture of each agent and one diff of
their escape vocabularies, and it was available from the first round.

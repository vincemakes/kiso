# DC-17 — the editor still reserved the retired box's walls

- **id:** DC-17
- **class:** width authority
- **severity:** P2 — three columns of every typed line, and two
  authorities disagreeing
- **agent:** kiso 0.16.3
- **found by:** an adversarial review comparing the editor's reflow
  width against the compositor's walk cap
- **status:** FIXED (0.16.4 working tree)

## The measurement

```ts
// editor.ts
const maxW = Math.max(1, W - leadW - 4); // W6: the box's walls (2+2)
// compositor.ts
… cap the walk at W - 1 (the drawn cursor's own cell)
```

The box was retired this round (law 1.1). The editor kept reserving its
two walls plus their two spaces; the compositor reserves one cell for the
drawn cursor. Two authorities on the same row, three columns apart.

Visible effects: the horizontal scroll marker appears with three blank
columns still free at the right edge, and the cursor can never occupy
the row's last three cells.

The R2 commit and `boxTop`'s own comment both claim the change "returns
two columns to the input by dropping the box's sides". It returned them
to the FRAME and not to the editor, so nobody typing ever got them.

## The cause

The R2 editor diff touched exactly one thing — DC-7's OSC branch —
because that was the finding being worked. `#reflow` is 2,000 lines away
from the rails that changed, and nothing links them but a comment.

The W23 cursor contract exists precisely to pin that the frame and the
editor agree about the column; it pins the CURSOR's column, which both
compute the same way, and not the LINE's width, which they did not.

## The fix

`W - leadW - 1` — the same one column the compositor reserves, on the
same row, for the same reason.

# DC-41 — ctrl+o is expand-tool-output in the reference implementation, and the history viewer in kiso

- **id:** DC-41
- **class:** keymap / muscle-memory divergence from the reference
  implementation — not a rendering defect
- **severity:** P3 — nothing breaks; a user arriving from the reference
  presses ctrl+o expecting to open the tool output in front of them and
  gets a different surface. Reported by the owner (2026-09-02).
- **agent:** kiso 0.19.0+ (R5 gave ctrl+o to the transcript viewer).
- **status:** RESOLVED — the owner ruled **(a) swap** on 2026-09-02 and
  it ships in 0.21.0: `ctrl+o` is the expand key, the viewer takes
  `ctrl+r`. The brief's proposed landing for the viewer was `ctrl+t`;
  the check it asked for ("confirm it is free in the reference's keymap
  so no second collision is created") came back NEGATIVE — `ctrl+t` is
  bound there to collapsing thinking blocks, a real main-flow action, so
  it would have rebuilt this same defect one notch smaller. Every free
  control key in kiso's dispatch (ctrl+b f g l n p t x) is bound to
  something there; `ctrl+r` is the cheapest collision, since it renames
  a session and kiso has nothing to rename. Recorded in design.md §9.0.

## The divergence, measured from both sources

The reference implementation
(`ref_repos/pi/.../core/keybindings.ts`, and the installed 0.84.x):

```
app.tools.expand   ctrl+o        "Toggle tool output"
```

ctrl+o toggles the tool output OF THE THING IN FRONT OF YOU — it
expands and collapses a tool result inline, in the stream. It is the
primary way to see more of a call's output without leaving the flow.

kiso (`packages/tui/src/editor.ts`, `compositor.ts`):

```
ctrl+o   the transcript VIEWER (R5) — a reader over the turn's record
ctrl+r   the EXPAND key (W15) — opens a fold in place, in the stream
```

So the two products put the SAME gesture on two different jobs:

| gesture | reference implementation | kiso |
|---|---|---|
| expand this call's output, in the stream | ctrl+o | **ctrl+r** |
| open a scrollable reader over the record | (no direct equivalent) | **ctrl+o** |

kiso's own design.md §9 acknowledges the borrow and its cost: "the same
key the reference implementation uses, so the muscle memory transfers
even though what it opens is not the same surface." The owner's report
is that the second half of that sentence is the problem: the muscle
memory transfers the KEY and betrays the ACTION. A reference user
reaches for ctrl+o to open the tool output and gets a full-screen-ish
history reader instead.

## Why kiso is arranged this way (the record, not a defense)

- ctrl+r is kiso's expand-in-place, and it predates the viewer (W15,
  DC-27/28/35). It has one target and says which (design.md §7.7).
- R5 (0.19.0) needed a key for the viewer and took ctrl+o because it
  was "free" and matched the reference's key, betting the surface
  mattered less than the finger.
- kiso cannot expand-in-place the way the reference does WITHOUT a
  viewer, because §7.1 makes committed rows immutable — an expansion
  can only append (ctrl+r) or open a redrawable surface (the viewer).
  So the reference's "toggle in place" and kiso's ctrl+r are already
  the same intent under different constraints; the mismatch is only
  which glyph the finger learned.

## Options for the ruling

- **(a) swap.** ctrl+o becomes kiso's expand-in-stream (today's ctrl+r
  job), ctrl+r or another key takes the viewer. Aligns the primary
  gesture with the reference; costs a re-learn for existing kiso users
  and moves the key design.md §7.7 pins.
- **(b) alias.** ctrl+o, on a settled tool fold with the composer idle,
  expands that fold in place (the ctrl+r action); ctrl+o on an empty
  composer with nothing to expand opens the viewer. One key, the
  action inferred from what is under it — closest to "it does what a
  reference user expects when there is a call to expand." Costs a
  precedence rule and its gate.
- **(c) keep, and say so.** Leave the split; make the divergence
  explicit in the keys sheet and the opening hint (ctrl+o = look back,
  ctrl+r = expand). Cheapest; bets that a one-line hint retrains the
  finger faster than a keymap change.

Recommendation deferred to the owner — this is a feel call, and the
owner is the one who felt it. My lean is (b): it is the only option
where the reference user's reach for ctrl+o does the thing they meant
whenever there is a fold under it, and still gives kiso its viewer when
there is not.

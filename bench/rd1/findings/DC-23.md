# DC-23 — search_text rejects a file path with a raw errno

- **id:** DC-23
- **class:** tool ergonomics / error surface
- **severity:** P2 — two wasted model round-trips per occurrence, and a
  filesystem errno on the human's screen
- **agent:** kiso 0.16.7
- **found by:** the 0.16.7 real-model dogfood (deepseek-v4-flash, 28
  tool calls, a read-only question about this repo)
- **status:** OPEN

## What happened

Twice in one session the model asked to search INSIDE a file:

```
search_text {"path": "packages/tui/src/compositor.ts", "pattern": "collapse|one line|single line|turn"}
  -> search_text failed: ENOTDIR: not a directory, scandir '/Users/…/packages/tui/src/compositor.ts'
```

It is the obvious thing to ask for — the file was already known and the
question was where in it something is decided — and the tool only takes
a directory. The model tried it twice, so the error did not teach it
anything either.

Two costs, and the second is the larger one:

1. two round-trips bought nothing;
2. `ENOTDIR: not a directory, scandir <abs path>` is a Node errno, and
   it reached the screen unedited. The product's own rule is that a
   failure keeps its words — but the words should be the tool's, not
   libuv's.

## The options

1. **Accept a file path** — search that one file. This is what the
   caller meant, it is one `stat` away, and it removes the failure
   rather than explaining it.
2. **Keep the restriction, fix the sentence** — "search_text takes a
   directory; pass its parent and a `glob` to look inside one file."
   Cheaper, and still costs the round-trip.

(1) is recommended: the tool's job is to find text, and a file is a
place text lives.

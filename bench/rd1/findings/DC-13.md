# DC-13 — the resume picker filters on a column it no longer shows

- **id:** DC-13
- **class:** interaction / search
- **severity:** P1 — the picker's only interaction, from the moment the
  id left the row
- **agent:** kiso 0.16.4 working tree (introduced by this round's own
  row change)
- **found by:** a PTY needle going red — `tui2-r2-resume-picker` types
  `ben` and expected `bench-refactor` on screen. The id was gone, so the
  needle failed; the filter still matched it, which is the actual defect
- **status:** FIXED (0.16.4 working tree)

## The measurement

Rows after the owner's ruling (2026-08-27) that the picker row shows
the TITLE only and drops the id:

```
╌╌╌ sessions ╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌
▌ dogfood the tui        1h · 8 turns · interrupted mid-run
✓ refactor the bench     2h · 3 turns · completed clean
```

`sessionFilter` matched `card.id` and nothing else. So:

- typing `dogfood` — the words on the row — matched **nothing**;
- typing `ben` — a fragment of the id `bench-refactor`, which is not on
  the screen anywhere — narrowed the list to one row, for a reason the
  screen never explains.

## The cause

Mine, this round. Moving the title into the row was a *display* change
in `rowSpans`; `sessionFilter` is thirty lines above it and was not
touched. The two are one feature — a list you can see and a list you can
narrow — and they were changed as if they were two.

The general shape: **a search that reads a field the view does not
render is a search the user cannot form a model of.** It fails silently
in both directions, which is why nothing caught it until a needle that
happened to type an id went red for a different reason.

## The fix

Search `title ?? id` first, then the id. Both stay haystacks: `kiso
sessions` prints ids, and a human who copied one must be able to paste
it here. At equal run length a TITLE hit outranks an id hit, because the
title is what the person was reading.

The determinism is unchanged — subsequence, ranked by longest contiguous
run, then by the matched haystack's length, then lexically — so a row
under the cursor still never moves because two candidates tied.

## Red before green

Five cases appended to `tui2-r2-session-picker.test.ts`: a title match,
an id match, the title-outranks-id tie-break, the untitled fallback, and
the empty query. Red 2/5 before the fix (the two title cases returned
`[]`).

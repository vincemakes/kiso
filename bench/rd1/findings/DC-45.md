# DC-45 — the chip's cut notice never folded, so a wide paste in a narrow terminal killed the session

- **id:** DC-45
- **class:** invariant 1 violation (a row wider than the terminal),
  reached from ordinary use
- **severity:** P2 — kiso THROWS and the session ends. Nothing is
  corrupted (the turn had not been sent) and the next launch is clean,
  but the human loses the composer's contents and the run.
- **agent:** every version that has had the chip's truncation notice.
  Found 2026-09-03 during R13.
- **status:** FIXED in this round, red before green
  (`r9-chip-wash.test.ts`, two cases).

## The measurement

`UserMessage` bounds the chip at `USER_CHIP_ROWS = 12` and, when a
message is longer, appends one row outside the reverse video:

```
+3 more lines · sent in full
```

That sentence is **30 columns wide and was written at a fixed length**:
no fold, no cut, no tier. Every other row of the chip is padded to the
terminal's width by `displayWidth`; this one was pushed as-is.

A paste of thirteen lines is what reaches it. In a terminal narrower
than the sentence, the compositor does exactly what it promises:

```
kiso-tui invariant 1 violated: a line of visible width 30 > 20 was about
to be emitted
```

Measured through the real `Body` at W=20, H=24 with a 15-line paste.

## Why it survived this long

The chip's width gates fold CONTENT, and the content half was always
right — `foldWords` at the chip's inner width, every row padded to `W`.
The notice is not content: it is kiso's sentence about the chip, added
after the fold, and it sits outside the reverse video precisely so it
reads as a different register. It left the fold behind with the surface.

The existing width case (`a word longer than the width still
hard-breaks`) used `"x".repeat(200)` at W=20, which folded into exactly
twelve rows — one under the cap. It never reached the notice.

R13 is what put it on screen: the chip's inner pad went from one column
to two (D4), the same 200 characters became thirteen rows, and the case
that had been passing for the wrong reason failed.

**The general shape, worth keeping:** a gate whose fixture sits one
element from a boundary is a gate that tests the boundary's near side
only. This one had been green for months on a case it never exercised.

## The fix

The notice takes the same discipline as every other metadata row in the
product (TUI2-R1.5 5, pin 4): tiers in a pinned order with the
SEMANTICS reserved. `sent in full` is the whole reason the row exists —
a bounded display of a complete message is not a truncated message, and
the row has to make that difference visible or it reads as data loss.
So the count gives way first, and `cutLine` is the backstop, so the row
fits at any width there is. The new gate walks W from 4 to 40 and
asserts the notice exists and fits at every one of them.

## Belongs with

Invariant 1 (a component that forgets to fold CRASHES — the crash is the
contract, not a symptom), TUI2-R1.5 5 (the reserved semantics), and
R13, whose chip change is what exposed it.

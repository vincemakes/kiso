# DC-28 — ctrl+r is a dead key mid-stretch, and it leaves a flipped flag

Status: FIXED in R4 (2026-08-30). Found in the R4 design review,
against 0.17.0. The standing act slot's gap frame gives the press a
visible target, so the toggle renders where it used to only mutate;
gated by `packages/tui/tests/r4-act-slot.test.ts` ("R4 D").
Class: silent no-op with a delayed, invisible consequence.
Surface: `packages/tui/src/compositor.ts` — `expandNext()` (:1181) vs
`#liveProjection` (:1850, the flight check at :1874).

## The defect

`expandNext()` scans the live cells from the newest backwards and takes
the first tool cell that is not pending:

```js
if (cell.kind === "tool" && cell.state !== "pending") {
    cell.expanded = !cell.expanded;
    this.#mark();
    return { kind: "toggled" };
}
```

Between two calls of an open stretch, the newest live tool cell is DONE.
It matches. So `ctrl+r`:

1. flips `cell.expanded`,
2. returns `toggled` — so control never reaches the `#collapsed` ring, and
   the press does not fall through to a settled fold either,
3. renders **nothing**, because the projection skips every done cell in
   the open segment before `expanded` is ever consulted:

```js
const flight = cell.kind === "tool" && !cell.done;
if (!flight) continue;
```

There is no tint to show for it either — the focus row is `continue`d at
the same line, before `focusToken` could be applied.

So the key does nothing visible, twice over: no expansion, and no
alternative action.

## The part that is worse than a no-op

The flag is still flipped. `cell.expanded` now carries a value the human
set blind, and it changes what a LATER expansion of that stretch renders —
the appended rows are the cells' own renders, and an expanded cell renders
differently. The user presses a key, sees nothing, and a minute later an
unrelated expansion comes out in a shape they did not ask for and cannot
connect to anything they did.

A key that does nothing is a papercut. A key that does nothing *now* and
something *later* is a state leak.

## Not covered by any gate

`packages/tui/tests/r3i-live-projection.test.ts` does not press `ctrl+r`
mid-stretch. The R3i round tested what the projection DRAWS across the
stretch's phases and never tested what the expand key DOES during them.

## Remedy

Two halves, and the round should take both:

1. **Give the press a visible target.** Under the R4 C3 standing act slot,
   the gap frame keeps the finished call's settled head in the slot, so a
   toggle has something to act on and the no-op disappears structurally.
   If C3 does not ship, `expandNext` must skip done cells inside an OPEN
   segment and fall through to the `#collapsed` ring instead.
2. **Gate it.** A test that presses `ctrl+r` between two calls of an open
   stretch and asserts both the rendered consequence and that no flag was
   mutated when nothing rendered.

# REL-0152-D15 — image paste waited for a signal the terminal never sends

- **id:** REL-0152-D15
- **class:** input / a feature that could not fire
- **severity:** P2 — a shipped feature that never ran
- **agent:** kiso 0.15.7
- **found by:** owner dogfood, 2026-08-26 ("cmd+V and ctrl+V both do nothing")
- **status:** FIXED

## The mistake

REL-0152-D11 shipped image paste keyed on an EMPTY bracketed paste. The
reasoning: a terminal cannot put binary into a byte stream, so pasting
an image would arrive as a paste with nothing in it, and that emptiness
would be the signal.

Half of that is right and the half that matters is wrong. The terminal
cannot send the image — and with no TEXT on the clipboard it does not
send a bracketed paste either. There is no empty paste; there is no
event at all. The hook was waiting for something the terminal never
emits, which is why the owner's cmd+V and ctrl+V both did nothing and
why no gate caught it: every case fed the editor an empty paste, which
is exactly the situation that does not occur.

## The fix

ctrl+V is the gesture. It arrives as 0x16, a byte the editor has always
received and thrown away as "other control", and it works whatever the
terminal decides to do about cmd+V.

The empty-paste route stays wired, because terminals differ and one that
does send an empty paste should behave the same way. Two doors, one
room.

0x16 must never reach the buffer: an unhandled control byte in a prompt
is a corrupt prompt, and with no hook wired ctrl+V is inert rather than
inserting itself. That is its own case.

## The lesson

The D11 gates tested the mechanism and not the trigger. Every one of
them fed an empty bracketed paste and asserted what followed — so they
proved the machinery works given a signal, and never asked whether the
signal happens. A feature whose entry condition is assumed rather than
observed can pass a full suite and never run once.

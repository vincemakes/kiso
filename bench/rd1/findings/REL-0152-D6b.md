# REL-0152-D6b — the picker still showed bare ids; the fix landed on the surface nobody uses

- **id:** REL-0152-D6b
- **class:** interaction / regression of an incomplete fix
- **severity:** P2 — the reported defect was reported fixed and was not
- **agent:** kiso 0.15.4
- **found by:** owner dogfood, 2026-08-25 — no title in the picker, so
  not fixed
- **status:** FIXED

## What went wrong

REL-0152-D6 changed the title in `SessionStore.list()` and I verified it
through `kiso sessions`. The surface the owner actually uses is the
resume PICKER, which does not read `list()` at all — it builds its own
cards in `apps/cli/src/session-cards.ts`, and that projection had no
title field. So the picker kept showing five rows of bare ids, which was
the entire complaint.

The verification was the failure. I checked the surface that was easy to
check from a shell instead of the one named in the report.

## The fix

`sessionTitle(records)` is exported from the runtime and is now the ONLY
definition. Both consumers call it: `list()` for `kiso sessions`, and
`projectSessionCard` for the picker. They cannot disagree again.

The picker row places the title after the age/turns meta and before the
note, bounded so the note — which can be the row that demands an action
("N uncertain executions") — keeps its room. On a narrow terminal the
existing span-fitting drops whichever no longer fits, in that order.

## The lesson

A fix is verified on the surface the report names. "It works in the
adjacent command" is not evidence about the picker, and reporting it as
one cost the owner a round trip.

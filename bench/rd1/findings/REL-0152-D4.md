# REL-0152-D4 — reaching the custom-answer row should BE the input

- **id:** REL-0152-D4
- **class:** interaction / affordance
- **severity:** P3 — a working path with an unnecessary step
- **agent:** kiso 0.15.3 (the row became reachable in that release)
- **found by:** owner dogfood, 2026-08-25
- **status:** FIXED, released in 0.15.4

## The behaviour

REL-0152-D3 made the "type your own answer" row reachable by the cursor.
Landing on it still requires a second gesture — enter — before the field
accepts text.

The owner's request: arriving at the row should already be the input, with
a dim placeholder, ready for the first keystroke.

## Why it is worth doing

Every other row in that list answers on arrival plus one commit. This row
costs arrive, commit, then type, then commit — two commits for one
answer, and the extra one has no meaning: there is nothing to confirm
about "I want to type".

It is also the row a user reaches when the four offered options are all
wrong, which is exactly when friction is least welcome.

## The shape (Claude Code's)

The reference is `PromptInput` in the vendored tree: a text field that is
always live, showing dim placeholder text when empty rather than
requiring a mode change to become editable.

For kiso that means the `custom` phase begins when the cursor arrives,
not when enter is pressed:

- arriving on the row sets `phase: "custom"` with an empty buffer;
- the row renders the placeholder in the dim palette until a character
  is typed;
- enter commits the typed answer, as it does today;
- **up/left must still leave** — the phase change cannot become a trap,
  which is the one real risk here: today `esc` backs out, and arrow keys
  are routed to the editor's buffer once the phase is `custom`.

That last point is why this is not a two-line change and why it belongs
with the editing batch rather than riding a patch: the key routing
between "walking a list" and "typing into a field" has to stay
unambiguous in both directions.

## Not to be confused with

RD1B-F6, which was the dock-LESS ask hanging forever. This is the docked
panel, working correctly, one gesture heavier than it needs to be.

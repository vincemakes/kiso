# DC-22 — the clean-replay batch scores from a temp tree, not from its archive

- **id:** DC-22
- **class:** bench reproducibility / gate
- **severity:** P1 for the release path — `npm run check` cannot pass on
  any machine whose temp directory has been swept
- **agent:** the RD-1B clean-replay artifacts (2026-08-24), unchanged
  since; NOT introduced by the R3 rounds
- **found by:** `npm run check` reaching `check-bench-repro` for the
  first time in several rounds (earlier runs stopped before it — see
  "why now")
- **status:** FIXED (owner ruled option 2, 2026-08-29) — and the
  published figures needed NO re-pinning: they re-derive against the
  existing `expected-clean.json`, unchanged

## The failure

```
[rd1:expected] FAIL — published figures moved:
  batches.rd1b-clean-kiso.grid.c1-r1.A0: PASS -> FAIL
  batches.rd1b-clean-kiso.grid.c1-r1.deterministic_recovery: PASS -> INVALID
  ... and 136 more
```

137 rows. The PRIMARY batches still re-derive exactly:

```
[rd1:expected] OK — every published figure re-derives (paired n=16, median 2.4x, aggregate 3.11x)
```

Only `--pin clean` moves.

## The cause (the diagnosis below stands; the root is one line of it)

`rescore.py` on the clean batch reports, per cell:

```
deterministic_recovery  end rows 0 (==1); NOT recovered to completion; missing:
  <TMP>/scratchpad/replay/work/kiso/c10-r2/work/src/a.txt:alpha: new, …
```

The clean batch's `score-manifest.json` files carry ABSOLUTE paths into
a replay work tree under the machine's temp directory. That tree still
exists; every leaf is empty, mtime today at 00:00 — the OS swept
`/private/tmp`. The scorer reads the filesystem for those cells, finds
nothing, and scores INVALID.

So the clean batch was never self-contained. It scored PASS only while
the temp tree it was recorded against happened to survive.

This is the exact class `check-bench-repro` was written for — its own
header says the tools "read the UNTRACKED working directory, so they
worked on the author's machine and nowhere else". The gate is right; the
artifact is what does not hold.

## Why now

The gate sits fourteenth in the `check` chain, after the test run. The
last several rounds' checks stopped before reaching it — a PTY scenario
burning its 60s wall starved vitest's `onTaskUpdate` RPC, so the run
failed at `npm run test` with every test green. With that fixed (R3g),
`check` reaches the bench gate, and the bench gate reports what has been
true since the temp sweep.

Nothing about the failure is new; only our ability to see it is.

## What it is NOT

Reproduced at HEAD with a completely clean tree (`git stash -u`): the
same 137 rows, byte for byte. It is not the R3 rounds' doing.

## The actual root, found after the first write-up

`relocate` (batches.py) knows ONE recording layout: it re-roots any
string carrying an `/out/<batch>/` segment onto the materialized
archive. The clean replay — added later, as RD1B-F8's "a fresh
directory per cell" — recorded under `<tmp>/replay/work/<agent>/<cell>/`
instead. Those strings have no `/out/` segment, so `relocate` returned
them untouched, by its own documented rule ("a string without one is
returned untouched, and whatever reads it will fail loudly, which is
the intent").

It did not fail loudly. It failed as a VERDICT.

And the archive held every one of those files the whole time:

```
rd1b-clean-kiso/c1-r1/work/NOTES.md
rd1b-clean-kiso/c1-r1/work/STATUS.md
rd1b-clean-kiso/c1-r1/ledger.jsonl
…
```

## The fix (owner ruling: option 2)

1. **`relocate` learns the second layout.** A string rule 1 does not
   match is re-rooted from its CELL segment (`c<N>-r<M>`) — the one
   component both layouts share and the one the archive is keyed by.
   Rule 1 runs first and is untouched, so the primary batches' paths
   are byte-identical and their figures cannot move.
2. **An unresolvable path is a SCORING ERROR, not a verdict.** After
   relocation, every path the manifest names must lie inside the batch
   root; a stray one raises `ScoringError` naming it. A missing FILE
   under the root stays a verdict — that is a real observation and the
   whole point of the `lost_work` axis. What is barred is looking
   outside the archive and calling the answer a result.

## Evidence

```
[rd1:expected] OK — every published figure re-derives (paired n=16, median 1.51x, aggregate 1.33x)   # clean
[rd1:expected] OK — every published figure re-derives (paired n=16, median 2.4x, aggregate 3.11x)    # primary, unmoved
[bench-repro] OK — 2 batches re-derive from the tracked archive in a fresh clone
```

**No re-pinning was needed.** The published clean-replay figures were
right; the scorer was reading the wrong filesystem. Re-pinning would
have written the broken reading into the record — the failure mode the
harness's own header warns about ("re-pinning without an answer is how
a benchmark starts lying slowly").

Red-first: with rule 2 of `relocate` removed, `rescore.py` now refuses
the clean batch by name —

```
c10-r2: 6 manifest path(s) do not resolve inside the batch — the archive
cannot supply this evidence and the cell must not be reported as scored
(first: <tmp>/scratchpad/replay/work/kiso/c10-r2/ledger.jsonl)
```

— where before it printed 137 INVALID axes and exit 0.

## The lesson worth keeping

A path-rewriting rule that silently declines to rewrite is a rule that
scores the wrong filesystem. The comment said the failure would be
loud; nothing enforced it. The enforcement is the second half of the
fix, and it is the half that would have made this a five-minute
diagnosis instead of a 137-row figure drift.

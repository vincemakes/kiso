# REL-0161-M1 — Terminal.app Marks the composer because the cursor is visible on a paste-armed line

- **id:** REL-0161-M1
- **class:** renderer / terminal-state contract
- **severity:** P2 — the composer wears bracket decorations on a stock
  Terminal.app, and the reference implementation's does not
- **agent:** kiso ≤ 0.16.0
- **found by:** owner dogfood + the owner's own C-probe, 2026-08-27
- **status:** FIXED in 0.16.1 — the hidden-cursor contract

## The mechanism, established by experiment

REL-0152-D1 closed with "the brackets are Terminal.app's Marks, not
text" (proven by copy — they don't come along). REL-0152-D20
established that kiso paints over the terminal's lines and attributed
the composer's marks to inherited line state. Both left one question
open: WHY the reference implementation's composer never earns a mark
of its own.

The owner's three-probe answered it, including one result no probe
had been designed for:

| probe | state at Return | marks? |
|---|---|---|
| plain `cat` | paste-mode off, cursor visible | none |
| `cat` under a kitty-protocol push | paste-mode off, cursor visible | none |
| `cat` under `?25l` | cursor hidden | none |
| **after the C-probe** (its `?25h` never ran — ctrl+C aborted the zsh list) | **cursor hidden at the SHELL** | **none — the shell's own prompts stopped being marked** |
| zsh prompt (normal) | paste-mode armed by zle, cursor visible | marked |
| kiso composer ≤ 0.16.0 | paste-mode armed, cursor visible | **marked** |
| the reference implementation's composer | paste-mode armed, **cursor hidden** (it draws its own) | none |

Terminal.app's "Automatically Mark Prompt Lines" infers a prompt where
**bracketed paste is armed AND the hardware cursor is visible**.
kiso's composer met both conditions; the reference implementation
keeps the hardware cursor hidden for its whole life and paints its own
cursor cell, and is immune. The startup byte captures agree: kiso
emitted no `?25l` outside frame brackets; the reference implementation
nets to hidden (`?25l`×4, `?25h`×1) from its first frame.

## The fix (0.16.1) — the hidden-cursor contract

1. the entry reset ESTABLISHES `?25l` (and repairs a killed
   predecessor straight into the desired state);
2. no frame ever emits `?25h`; every frame open re-asserts `?25l`
   (self-healing against stray output);
3. the composer draws its own cursor: the cell at the marker renders
   inverse (SGR 7…27) — a wide CJK glyph or an emoji pair inverts
   whole, a lone surrogate half is left unstyled rather than split,
   and the end-of-line cursor is an inverse space taken out of the
   pad, so the row still totals exactly W;
4. the hardware cursor still PARKS at the marker cell — the IME
   anchor is its position, not its visibility (CJK input keeps its
   candidate window placement);
5. `editor.exit()` restores `?25h` beside its paste-mode restore —
   the one hand-back point. `kill -9` leaves the cursor hidden: the
   same exposure the reference implementation accepts; the D19 entry
   repair covers the next kiso, `reset` covers the shell.

Gates: `packages/tui/tests/cursor-hidden.test.ts` (10). Declared
supersessions, named in the commit: the ?25l/?25h frame bracket
(apple-terminal-frames), the D19 entry `?25h` (enter-reset — the
cursor half inverts), and the contiguous-composer-text byte reads
(kc1/kc3/geometry/compositor read through SGR 7/27 now).

## The lesson

Five rounds of instruments measured what kiso WRITES. The mechanism
was in what kiso left SHOWING — a state, not a byte. The probe that
settled it cost three shell lines, and half of its answer came from
an accident (a ctrl+C that swallowed a restore). Design probes so
their failure modes are informative too.

# DC-11 — the opening screen taught a key the product does not have

- **id:** DC-11
- **class:** copy / honesty
- **severity:** P2 — the first screen, every session
- **agent:** kiso 0.16.3 (introduced by the R2 banner rewrite itself)
- **found by:** grepping for the `!` handler while working the audit's
  `!bash` row, and finding there is none
- **status:** FIXED (0.16.4 working tree)

## The measurement

`BANNER_KEYS` read:

```
esc interrupt · ctrl+c exit · / commands · ! bash · ctrl+r expand
```

`KEY_BINDINGS` — the one table `/keys` and the sheet both read — has no
`!` row. There is no bang handler in the editor, no passthrough in
dispatch, and `Body.terminal()` (the passthrough's renderer) has no
caller in the product.

## The cause

Mine. The R2 banner rewrite composed a keys row from what a terminal
agent's opening screen usually offers rather than from what this one
implements. `KEY_BINDINGS` was right there and was not consulted.

## The fix

The row names bindings that exist:

```
esc interrupt · ctrl+c exit · / commands · @ files · ? keys
```

A first screen that lies is worse than a short one. Whether kiso should
HAVE a bang passthrough is a separate question and not a visual round's
to answer.

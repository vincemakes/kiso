# DC-20 — an interrupted tool parks the commit pointer for the session

- **id:** DC-20
- **class:** liveness / durable-execution surface
- **severity:** P1 — the screen stops advancing and never recovers
- **agent:** kiso 0.16.6 and earlier
- **found by:** an independent review of R3b–R3f (fable), then
  reproduced as a unit gate
- **status:** FIXED (R3g working tree)

## The shape

An `esc` in the middle of a tool call leaves that call's cell with
`done: false` — the tool never returns a result, so nothing ever closes
it. The commit loop stops at the first cell that is not done:

```ts
while (this.#committed < this.#cells.length && this.#cells[this.#committed]!.done && !this.#held(...))
```

So ONE interrupt parks `#committed` for the REST of the session. Every
later turn's rows pile into the live region and leave it only through
the force-commit cap, which is the degraded path — and, per DC-19, the
path that can drop a row entirely.

This is very likely what the owner photographed as a session that
"stopped halfway".

## The fix

The turn's end closes an abandoned tool cell, exactly as it already
closed an open thinking cell and an open checklist block:

```ts
for (const c of this.#cells) {
  if (c.kind === "tool" && !c.done) { c.state = "done"; c.reason = "interrupted"; c.doneAt = Date.now(); c.done = true; }
}
```

`reason` is set rather than left null for two reasons: the row keeps
its words (`run_shell sleep 100 (interrupted)` — the interruption is
NAMED, never a silently finished-looking row), and the trouble
predicate then holds the turn unfolded, because law 1.3 says trouble is
never summarised away.

## Two blind spots found by fixing it

- **The fold's.** A DENIED call carrying no `reason` string left
  `isError` false and `reason` null, so `✦ thought 3s · read 20 files`
  could stand over a refused write. `#segmentHasTrouble` reads the
  verdict now.
- **The rollup's.** Closing an aborted call made it `done`, which let a
  run it never finished roll up as `explored 3 paths` — a sentence a
  failed or interrupted member makes false, over the row that was the
  only place that failure had words. The rollup obeys the same rule the
  fold already obeyed.

## Evidence

`packages/tui/tests/r3g-interrupt.test.ts`, 7 gates. Each of the three
fixes reverted independently, one at a time:

```
revert the interrupt-closing  -> 3 failed | 4 passed
revert the denied verdict     -> 1 failed | 6 passed
revert the rollup trouble rule-> 1 failed | 6 passed
```

## A gate that was not a gate

The first draft of the denial and interrupt gates keyed "this turn does
not fold" on the literal `✦ thought`. When the turn's user chip rides
the fold (A9) the line reads `✦  write it  · thought 3s · …` and that
literal never appears — so the assertion held whether the turn folded
or not, and both gates stayed green with the fix reverted. They key on
`/thought \d+s/` now, which both shapes carry.

# 0.47.1 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.47.1 is APPROVED.

0.47.1 is 0.47.0's polish: the four cosmetic findings from the agent's
0.47.0 dogfood (0470-F1 to F4). Nothing else moved. Use your daily
terminal; the owner's config is `full-access`, so step B starts kiso in
`default` mode.

```
npm install -g @vincemakes/kiso-code@0.47.1
kiso --version        # 0.47.1
```

## A. A cut note counts lines (F1)

1. Ask for a command whose output is one very long line (for example
   `node -e "console.log('x'.repeat(2000))"`), at 80 columns.
2. The card's note reads `… the start of this line   ctrl+o expands`,
   not `… 1 earlier line`.
3. A long ordinary output (`ls -la /usr/bin`) still reads `… N earlier
   lines   ctrl+o expands`.

## B. A refusal is said once (F4)

1. `kiso --mode default`, then ask for a file to be written.
2. Press esc at the approval panel.
3. The card reads `WRITE <file>   denied by you`, with nothing under it,
   and no `approval cancelled` row follows.

## C. Manual compaction (F2, F3)

1. In a session of at least five rounds, `/compact`.
2. The `COMPACTED` row is the last thing drawn: no `[summarized up to seq
   N]` under it.
3. When it covers one round, it says `1 round`.

## D. What would be a finding

- Anything that reads differently from 0.47.0 other than A–C.
- Anything that behaves differently from 0.47.0 in a pipe (`kiso -p …`).

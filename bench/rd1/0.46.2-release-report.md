## What is in it

| PR | what changed |
|---|---|
| #243 | **The remote boundary.** A saved "don't ask again for shell" rule no longer carries a destructive `git push` (force, force-with-lease, force-if-includes, a `+` refspec, mirror, delete, a `:branch` refspec, prune) or a publish (`npm`/`pnpm`/`yarn` … `publish`). In default and accept-edits it asks; with don't ask on it is refused with the reason and the run goes on. Full access, plan and an extension of the user's that allows it are unchanged |
| #250 | **"Lost track", said once, when kiso concludes it** (ADR-0058 Amendment 8). The status row counts only running tasks; the `◌ N unknown` segment is gone. A task kiso can no longer account for gets one transcript line, `✦ lost track of t3 (npm run dev) — it may still be running · /tasks shows it`: at once when the loss is heard, or as a session opens for a loss the model has not been told of. When the model's notice of the same loss arrives, the line is not printed again. `/tasks` labels it `lost track — may still be running`; `/tasks show` says why. Also a defect fix: a `ps` probe that fails for a moment no longer makes a running task `unknown` for good, and an end recorded after `unknown` is announced. The model's notice is unchanged (`status="unknown"`) |
| #251 | **A repository's config may only make kiso stricter.** A project `.kiso/config.json` whose `mode` is looser than the user level, that sets `dontAsk: false`, or that defines `models`, stops kiso at startup with a `ConfigError` naming the key and the rule; the fix is to move the setting to `~/.kiso/config.json`. A project may still pick one of the user's profiles with `model` |
| #252 | **The remote boundary reads registry writes, and reads dry runs as the tools do.** Under a saved shell rule these now ask each time: `npm`/`pnpm` `unpublish`, `deprecate` and `dist-tag` add/rm, and yarn's `tag add`/`rm`; npm's abbreviations of them (`npm pub`, `npm unp`, `npm dep`); a dry run the tool does not honour or that is switched off again (`--dry-run false`, `--dry-run --no-dry-run`, `deprecate`/`dist-tag` with `--dry-run`, yarn classic's `publish`); and git push options written as prefixes (`--mirr`, `--no-dry`). With don't ask on they are refused with the reason. Full access is unchanged |
| #244 | Test only. The unconfirmed-stop case waits for the runner's `stop_unconfirmed` record, not just a settled reading: on a loaded machine a first identity probe that fails reads `unknown` a moment before the record is written. It merges separately; it is not in the packed files |

## For hosts

### Action required

- **`@vincemakes/kiso-tui`: `TaskCountsOnRow` loses `unknown`** (#250).
  It is `{ readonly running: number }` now, and `tasksSegment` renders
  `● N tasks running` or nothing. A TS host that builds the object with
  `unknown` gets an excess-property error; one that reads `.unknown` gets
  a type error. Kept as a removal, not an ignored optional field: 0.x,
  and no known host renders kiso's status rows.

### Observable behaviour changes

- **A task's identity probe that fails for a moment** (the `ps` call
  itself) no longer makes a running task `unknown`. A runner last
  verified keeps that verdict for the next identify window. A stop still
  probes afresh and never signals an unverified pid. An end recorded after
  `unknown` is now announced as `ended` (#250).

### New optional capabilities (omit them and nothing changes)

- **`TaskDeliveryOptions.onLost(taskIds)`**, also accepted by
  `session.useTasks`: called with every loss the model has not been told
  of, at startup and as it is heard, so a host can tell its person at
  once. A loss a tool result reported (claimed) never comes (#250).

### Unchanged

- The model's task notice (`status="unknown"`) and the protocol's
  `TaskDeliveryItem`. #243, #251 and #252 are CLI only: no kernel or
  runtime change, no request byte.

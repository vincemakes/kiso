# 0.46.2 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.46.2 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.46.2
kiso --version        # 0.46.2
```

Run B in a throwaway repository with a LOCAL bare remote
(`git init --bare /tmp/r.git`, `git remote add origin /tmp/r.git`), and
answer **No** to anything that would reach a real registry.

## A. Lost track (#250)

1. Ask the model to run in the background:
   `sleep 2; kill -9 $PPID; sleep 30`. The command kills its own runner.
2. Within a few seconds, and without typing anything, the transcript says
   `✦ lost track of t1 (sleep 2; kill -9 $PPID; sleep 30) — it may still
   be running · /tasks shows it`. The status row stops counting it, and
   there is no `◌` anywhere.
3. Send any message. The line is not printed a second time.
4. `/tasks` labels t1 `lost track — may still be running`. `/tasks show
   t1` first says "its runner is gone without recording its end".
5. On reopen: ask for `sleep 20; kill -9 $PPID; sleep 30` in the
   background, exit and choose "leave it running", wait 25 s, then reopen
   the session (`kiso resume`). The line appears before you type.

## B. The remote boundary (#243, #252)

In default mode, answer one shell call with "Yes, and don't ask again for
shell". Then ask the model to run each of these; each must ASK again:
- `git push --force origin main` (to the local bare remote);
- `git push --dry-run --no-dry-run --force origin main`;
- `npm publish --dry-run false` (answer No);
- `npm dist-tag add some-pkg@1.0.0 beta` (answer No).

`git push origin main` still runs on the saved rule. With don't ask on,
the same four are refused with the reason, and the run goes on.

## C. A repository's config may only tighten (#251)

In a throwaway project, `.kiso/config.json`:
1. `{ "mode": "full-access" }` while your own mode is default: kiso stops
   at startup with a message naming `mode` and the rule.
2. `{ "models": { … } }`: kiso stops at startup, naming `models` and your
   user config.
3. `{ "mode": "plan" }`: allowed (stricter).

## D. What would be a finding

- A lost-track line that never appears without a message, or that appears
  twice in one session.
- A command on the boundary list that runs on a saved shell rule.
- A project config that loosens anything without an error.
- Anything in the 0.46.1 checklist that behaves differently on 0.46.2.

## What is in it

| PR | what changed |
|---|---|
| #285 | **The Responses adapter sends `strict: false` on every tool.** With the flag ABSENT, the ChatGPT backend forced every declared property into each call, and the model filled the optional ones with placeholders. On the owner's disk, 9 gpt-sol sessions show it: `read_file` sent an offset on 58 of 58 calls; `edit_file` sent both its forms on 56 of 57, so the form check refused every edit; `shell` sent `readyWhen: ""`, which matched the first output and detached one-shot commands into background tasks. The owner-approved discriminating run settled the cause, one request per arm on gpt-6.1-sol: absent → all four optional shell fields; `false` → `command` alone. The schema goes out as kiso wrote it, and the kernel stays the one validator. This reverses the adapter's earlier "no `strict`" note |
| #286 | **Thinking draws its paragraphs' inline markdown.** A reasoning summary opens on a `**title**`, and its asterisks showed. Each paragraph now goes through the answer's own `inlineSpans`, with the grey italic as the style every span closes back to; a marker with no closer stays literal while it streams. Blocks, the pipe and colour-off are unchanged (design.md §7.2) |
| #287 | **Screen names for kiso's own tools** (the owner's names): `task_stop` → stop task, `delegate` → subagents, `read_skill` → read skill, `ask_user` → ask user. Display only; the model-facing names stay. A third party's or an MCP server's tool still prints its own name |

## Findings

- **0473-F1 — kiso omitted `strict` on Responses tools from the start.**
  On the owner's disk, every gpt-sol session since 2026-09-09 shows the
  forced fields, including the 2026-09-29 cache-routing round's sessions:
  their edits also sent both forms. No gate saw it, because the bench runs
  DeepSeek and no test drove a GPT model's tool calls. The free fix for
  the gap: scan the session logs on disk per model and per tool before
  each release (proposed to the owner; not yet ruled).

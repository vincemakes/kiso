# 0.46.1 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.46.1 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.46.1
kiso --version        # 0.46.1
```

## A. Everything in the 0.46.0 checklist

`bench/rd1/0.46.0-dogfood-checklist.md`, on 0.46.1 (`/status` ends with
`version 0.46.1`).

## B. The effort is remembered per profile (#221)

1. In a session, pick an effort: `/model <profile> high` (or the `/model`
   panel with a level). Quit.
2. Start a NEW session (`kiso`, not `kiso resume`) on the same profile.
   `/status` and the status row show the effort you picked, not the
   default.
3. Resume the first session with `kiso resume`. It keeps its own
   recorded binding.
4. Pick an effort the model does not have, if one exists for your
   profile. The note reads "this model's default (it has no …)", and the
   new session starts at the model's default.

## C. What would be a finding

- A new session that does not start at the remembered effort, or a
  resumed one that does.
- A first request refused because of a remembered effort.
- Anything in the 0.46.0 checklist that behaves differently on 0.46.1.

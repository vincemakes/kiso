# 0.45.2 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.45.2 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.45.2
kiso --version        # 0.45.2
```

## A. Everything in the 0.45.0 checklist

`bench/rd1/0.45.0-dogfood-checklist.md`, on 0.45.2 (`/status` ends with
`version 0.45.2`).

## B. The one change: a long streamed answer no longer waits on the disk

#198 stops the session store syncing every streamed fragment (text,
thinking and a tool call's arguments as they stream). Every other event is
synced exactly as before.

- Ask for one large file in a single write (for example "write a
  1,500-line HTML page to big.html in one write_file call"). The stream
  and the turn's end arrive without a pause after the model finishes;
  the file is complete.
- Quit and `kiso resume` that session: it loads, and the transcript
  shows the same turns.
- Optional: kill the kiso process with `kill -9` while it is streaming,
  then `kiso resume`: the session loads and the unfinished turn is
  handled as on 0.45.1; nothing is reported corrupt.

## C. What would be a finding

- A stall at the end of a long streamed answer or a long `write_file`.
- `kiso resume` reporting a corrupt session after a normal exit or a
  `kill -9`.
- Anything in the 0.45.0 checklist that behaves differently on 0.45.2.

# 0.46.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.46.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.46.0
kiso --version        # 0.46.0
```

## A. Everything in the 0.45.0 checklist

`bench/rd1/0.45.0-dogfood-checklist.md`, on 0.46.0 (`/status` ends with
`version 0.46.0`).

## B. The approval tiers and the don't-ask switch (#203)

1. `kiso --mode full-access --dont-ask`, on a task that invites a question
   (an unclear direction, a trade-off). The model never asks (it has no
   ask tool), picks a default and finishes. No approval panel and no
   question panel appear. The status row reads `▸ full access · don't
   ask`.
2. `kiso --mode bypass` behaves as full-access. The status row reads
   `▸ full access`, and `/settings` shows the mode `from --mode (written
   "bypass")`.
3. Optional: `kiso --mode dontAsk` is default plus the switch. A write is
   denied with `[dontAsk] … would ask — denied` and the run goes on.
   Shift+Tab shows `don't ask → off`.

## C. Background tasks (ADR-0058)

1. **A service.** Ask it to start a small server in the background, check
   it with curl, fix something, restart it, check again, and stop it.
   - The start's result says `ready — the output contains …` (it waited
     for the ready line).
   - The stop's result says `stopped task tN (SIGTERM; it ran …)`.
   - Nothing arrives after its final answer: no second closing message.
2. **A slow command it needs.** Ask it to run a test suite that takes
   over a minute. It runs the suite in the foreground with a long enough
   wait, and does not background it and sleep.
3. **A command past its wait.** Ask for `sleep 90; echo done` with the
   default wait.
   - After 60 s the result says `still running after 60000 ms; continued
     as background task t1`.
   - The status row shows `● 1 task running`.
   - When it ends, the model is woken once and says so. The transcript
     shows a task row, not your chip.
4. **ctrl+b.** While a foreground command runs (`sleep 30`), press
   ctrl+b. The row shows `ctrl+b background` before you press it. The
   command moves to the background at once, and its result says "moved
   to the background by the person".
5. **A steer.** While a foreground command older than 2 s runs, type a
   message and press Enter. The command moves to the background, and
   your message lands without waiting for the command.
6. **`/tasks`.**
   - `/tasks` lists the session's tasks.
   - `/tasks show t1` shows the last output.
   - `/tasks stop t1` answers `t1: stop requested`. The list then shows
     it `stopping`, and then `stopped`.
   - Nothing of this reaches the model.
7. **Exit with a live task.** Leave a background task running and press
   ctrl+d. The question reads `1 task is running`, with `stop all and
   exit`, `leave 1 background task running` and `stay`.
   - "leave" exits and the process keeps running.
   - "stop all" stops it and says so.
8. **Background explorers.** Ask for two independent questions about a
   repository, each given to its own explorer with `background: true`.
   - The model ends its turn.
   - When both explorers are done, ONE notice brings both answers, and
     the model is woken once.
9. **The verifier role.** A `delegate` with `role: "verifier"` works. The
   name `tester` is refused with a message naming `verifier`.

## D. What would be a finding

- A request after the model's final answer that only acknowledges a task
  notice.
- A `background` + `readyWhen` start that returns before the ready line,
  or a "not ready" result that reads as ready.
- A task that keeps running after "stop all and exit", or a "leave" that
  stopped it.
- A wake that comes twice for one group, or never comes.
- A steer that waits behind a shell command older than 2 s.
- Anything in the 0.45.0 checklist that behaves differently on 0.46.0.

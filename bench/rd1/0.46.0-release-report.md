# 0.46.0 — release report (APPROVED)

Background tasks (ADR-0058, steps 3a–3e and Amendment 7), the four
approval tiers with a don't-ask switch, the verifier role, and native
Windows support behind the install gate. Everything below merged to
`main` through its own PR with the required `check` green; this release
adds only the version bump.

- **Candidate:** 17 tarballs packed from the release branch's bump commit
  (every `dist` deleted and rebuilt first; the publishable list derived
  from the workspaces), installed isolated; the release smoke and the
  kill -9 demo ran on them.
- **Lockstep:** new capability and one removed role name → a MINOR under
  0.x; 17 packages.
- **Kernel:** 2,192 / 2,200 lines (0.45.x: 2,185; #211 added 7).

## For hosts

### Action required

- **The delegate role `tester` is gone; it is `verifier`.** A host, a
  prompt or a saved task naming `tester` gets a schema error with the
  new name in it. There is no alias (#218).

### Observable behaviour changes

- **Approval decisions are recorded under the new tier names.** New
  sessions write `decidedBy: "mode:full-access"` (formerly
  `mode:bypass`) and `mode:default`. `--mode bypass` and
  `"mode": "bypass"` keep working and mean full-access. `dontAsk` is a
  switch, not a tier: `--dont-ask`, `KISO_DONT_ASK`, `"dontAsk": true`,
  `/dont-ask`; the old `dontAsk` mode spelling means default plus the
  switch (#203).
- **With tasks wired** (`session.useTasks(manager)` and a `tasks` option
  on the coding tools), the model-facing shell changes:
  - a command still running after `foregroundMs` is **promoted to a task,
    never killed**; `timeoutMs` is accepted as `foregroundMs` until 0.47;
  - `task_stop` **blocks up to 8 s** and reports how the task ended;
  - `background: true` with `readyWhen` **blocks until the ready line**
    (up to `foregroundMs`), and is released by ctrl+b, a steer or Esc;
  - transitions reach the model as `user_input` events with
    `source: "system"` and `via: { kind: "tasks", items }`, inside a run
    or as a wake run; a transition a tool result already reported is
    not noticed again;
  - the first request of a session is **+1,391 bytes** larger than
    0.45.3's (the shell's task parameters, `task_stop`, `delegate`'s
    `background` flag, the system prompt; measured on a local mock).

  A host that wires no tasks keeps 0.45's shell, byte for byte.
- **A steer no longer waits behind a detachable foreground shell
  command** older than 2 s (it is moved to the background, and its result
  says why). A foreground `delegate` child (implementer, verifier) still
  holds a steer until it ends (3e).
- **Summaries name background tasks** the model was told of, at the last
  state it was told (`Background tasks, as you were last told: …`).
- **On all platforms:** `edit_file` keeps a CRLF file CRLF and returns
  the written bytes' revision; a CRLF `SKILL.md` is read (#207).
- **On Windows (library hosts; the CLI is still gated):** the shell runs
  through Git Bash (`KISO_BASH` overrides; no bash → an error result
  coded `KISO_NO_BASH`); a process tree is ended with `taskkill`; a
  runner is signalled through its journal only; the session store, task
  journal and profile flush in a way Windows allows (before this, no
  session could run there) (#207, #220).

### New optional capabilities (omit them and nothing changes)

- **Tasks:** `session.useTasks(manager, { wake, onWake, windowMs,
  autoDetachMinAgeMs })`; the `TaskManager` and the journal types from
  `@vincemakes/kiso-runtime/internal` (internal while the public shape
  settles), including `awaitSettled`, `registerDetachable` / `detach` /
  `detachAll`, `stopAll`, `identifyEveryMs`, and `TaskInfo.agent` /
  `TaskInfo.claims`; `processTaskBackend()` and the `tasks` option of
  `@vincemakes/kiso-tools-node`. The journal's record types are
  `planned` (with `launch` and `agent`), `runner_started`,
  `command_started`, `ready`, `stop_requested`, `stop_unconfirmed`,
  `terminal` and `result_claimed` — a reader should skip types it does
  not know.
- **Background subagents:** `createSubagentExtension({ tasks,
  backgroundMax, backgroundMaxTurns })` (defaults 20 and 32). Without
  `tasks`, the `delegate` schema is byte-identical to 0.45's.
- **A per-run turn budget:** `session.run(input, { maxTurns })`.
- **The child-only CLI flags:** `kiso chat --task-file … --max-turns N
  --result-file PATH`.

The change surface spans the tool schema, the execution path and the

### The pre-release evaluation (ADR-0058 §11), two rounds

DeepSeek V4.1 Flash through Command Code, both arms, effort none; the
candidate against the published 0.45.3, interleaved; margins `bm1-a1`
(median cost-weighted delta ≤ +20%, median wall ≤ +25%; a single pair
over +50% is reported, not blocking). Criteria frozen before each round
(kiso-doc `readykit-0460-evaluation-2026-10-04.md`,
`readykit-0460b-evaluation-2026-10-05.md` with Amendment A1).

**Round 1 (eval-0460, the build before #229)** passed its blocking gates
(T3 +2.7%, T5 −0.2%, verify 84/84) and failed two of three expectations.
It found two defects, fixed in #229:

- **0460-B1:** the `background` description invited "long jobs"; the
  model backgrounded a 90 s test run it needed and slept on it (L1
  +48.8%).
- **0460-B2:** `task_stop` returned before the end, so its `stopped`
  notice landed after the final answer and bought one more request (4 of
  6 legs); `background` + `readyWhen` returned at once and the next
  command raced the server (L2 +78.3%).

F1 never fanned out on either arm, an instrument error (0460-I1).

**Round 2 (eval-0460b, this candidate's code),** 78 legs, 0 void, no
sleep, $0.236:

| workload | cost (median) | wall (median) | reading |
|---|---:|---:|---|
| T3 everyday coding, 12 pairs | **−10.3%** | +2.4% | PASS |
| T5 long session, 12 pairs | **−1.9%** | +3.8% | PASS (pair T5-8 +50.9%, reported) |
| L1 slow test, 6 pairs | **+4.9%** | **−3.4%** | the background misuse is gone: 5 of 6 legs never backgrounded the suite, none slept on it |
| L2 managed service, 6 pairs | **+65.4%** bench-weighted; **≈ +23%** at DeepSeek's prices (means) | +20.9% | every gate green: 0 requests after a final answer, 0 actions before being told ready, 0 notices |
| F1b background agents, 6 legs (rc only) | mechanism probe | — | PASS (Amendment A1 re-run) |

**L2's remaining cost is the managed lifecycle, not waste.** The
candidate averages 9.7 requests per task against the control's 6.2. The
control starts, probes and kills its server in two `nohup … &` one-liners.
The candidate starts the task and is told it is ready, probes, stops it
and is told it stopped, then does the same again. Each extra request
re-sends the conversation, mostly from the cache.

- The bench's metric (fresh + 0.1 × cached input; output not counted)
  reads +65.4%.
- At DeepSeek's prices (cached input at 2%, output counted), the means
  are $0.00097 against $0.00078 per task: +23%, about $0.0002 (the
  medians, $0.00095 against $0.00077, give the same +23%).

What the extra requests buy: the server is a tracked task (listed in
`/tasks`, stoppable, stopped at exit), and its readiness and its end are
facts the model is told. Accepted by the owner for 0.46.0; no compound
task operation is added to shrink the number.

**F1b** (rc only; the control has no background delegation, which
reverses §11's F1 paired wall comparison): 36 background explorers;
child requests p50 5 / p90 7 / max 8; 0 budgets spent; 0 sleeps or polls.
In the re-run, every leg verified, each group was delivered exactly once,
and each leg woke once. The first six legs lost their wake to the bench's
stdin feeder (it closed stdin the instant the last child ended), not to
kiso. The fix is #232, Amendment A1; the paired legs were unaffected.
D6's default stays 32 (the owner): four real explorers on this machine
took 10, 12, 14 and 17 requests.

**The static rent** (0460-R1): +1,391 bytes per request over 0.45.3
(the 3f estimate was 150–200 tokens; the measurement is about 348).
T3 and T5 show no regression at the paired level; recorded as cost
debt for a later round.

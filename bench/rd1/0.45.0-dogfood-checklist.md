# 0.45.0 — dogfood checklist (for the owner's manual pass)

The release rule: after the publish, the agent runs one real-model session
on a real task, and the owner runs an independent pass. Both go into the
record before 0.45.0 is APPROVED.

```
npm install -g @vincemakes/kiso-code@0.45.0
kiso --version        # 0.45.0
```

## A. A normal session

A session on a real task behaves as 0.44.0 did. The banner still reads
`[4 extensions: built-in: mcp, skills, subagent, ask]`; `/status` ends
with `version 0.45.0`.

## B. Steer: Enter while a run is working (ADR-0057)

Give it a task that takes several steps (reading a few files, a test
run). While it works:

- Type a correction and press Enter. The row stays above the editor as a
  dim chip, and the status reads `+1 steer`. Nothing is interrupted: the
  step in flight finishes.
- At the next step the chip lands as your message and the model's next
  step answers it — the same run, no restart, no separate turn.
- Two lines typed before it lands become ONE message (`+2 steer`, then
  one landing).
- While an approval is open, a steer waits; it lands after you answer.

## C. Taking a steer back

- Type a steer, then, before it lands, press `↑` on an empty editor: the
  text comes back into the editor and the chip disappears.
- Type a steer, then press Esc: the run stops as before, and the steer
  that had not landed is back in the editor, not lost.
- Type a steer, then alt+Enter with a new line: the run stops and ONE
  message goes out, your new line first, then the steer.

## D. A steer that arrives as the run ends

- Type a steer just as the model is writing its final answer. It is
  never dropped: either it lands in that run, or the run ends and the
  steer is sent at once as your next message.

## E. Piped input is unchanged

```
printf 'say one\nsay two\n' | kiso
```

Two turns, one per line — no steering on a pipe.

## F. GPT with an effort (#175, #176; only if you use that profile)

- `/model <your GPT profile> high`, then a task: the reasoning summary
  shows as thinking (ctrl+t toggles it as before).
- The status row shows no cache figure on the ChatGPT backend (by design
  since OR-10). The cache is visible in the session's trace
  (`~/.kiso/projects/<project>/traces/<session>.jsonl`): each request's
  `cacheRead` should grow over the turns; before 0.45.0 it stayed near
  the static prefix.

## G. What would be a finding

- A steer that vanishes (neither lands nor returns to the editor).
- A steer that lands while a tool is still running or an approval is
  open.
- A run restarted, or a second turn started, by a steer.
- Any behaviour that differs from 0.44.0 on the same task when you never
  press Enter during a run.

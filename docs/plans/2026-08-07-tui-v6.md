# TUI v6 — the one-compositor rewrite (round record)

- Date: 2026-08-07
- Release: 0.1.32
- Ruling: ADR-0046 (same round)

## Scope

Retire `body.ts` + `dock.ts` (the two-writer split — the seam behind
every finding since #13); ONE compositor owns every byte of the screen.
The CLI (apps/cli/src) is byte-identical: the compositor implements the
`Body` mutation façade + the `Dock` chrome façade. Zero diff in
core/cli code; the round's diff is packages/tui + tests + the lab.

## Architecture (ADR-0046)

- `Component{render(width): string[]}` + `Container`; one `doRender`.
- Event-driven: dirty flag → 16ms-coalesced frame; spinner = on-demand
  one-shot (no heartbeat timer — #15 becomes structural).
- `lines[] + commitIndex`: commits via the CUP-free real-LF scroll
  (`\x1b[1B\n`); committed bytes never re-emitted; live region hard cap
  **H−1** lines, overflow force-commits the oldest live line — the one
  sharp edge (risk 1), asserted by the VT-emulator gate.
- Two crash invariants: ① visible width ≤ W per emitted line (pi
  tui-main-screen.ts:447-473 — crash with diagnostics, no silent
  truncate); ② live-region redraws are relative moves + CHA only; CUP
  exists only in the full-redraw path (first frame, resize).
- Cursor: the focus component embeds an APC marker; the compositor
  locates/strips/positions from the frame — no side-channel cursor
  bookkeeping.
- Slots: chatContainer (Banner/UserMessage/AssistantMessage/
  ThinkingFold/ToolExecution/ErrorLine/Recap — render.ts feeds the
  original text) → statusContainer → editorSlot (exactly one of
  Editor | ApprovalPrompt | MenuSelect — focus follows the occupant) →
  footer. Approval/menu = slot swap, not overlay.
- Layout at H rows: content rows 1..H−3, status H−2, input H−1,
  footer ╌ at H. (The old upper separator retires; ONE dotted row.)
- Exit keeps the `\x1b[r` byte (the "no broken terminal" contract).
- Overlay composition, mouse, images, markdown, suspend-passthrough:
  OUT OF SCOPE. TODO: the $EDITOR scenario needs opencode's suspend +
  the two-sided cache-clear lesson.

## Gate re-baseline (risk 3 — one by one, old → new + reason)

- **storm (#16a)** — old: "zero LF during the resize storm" (≤ 1 LF,
  the recap's trailing blank commit). NEW: the resize repaint is a full
  live-region redraw with CUP and ZERO LF; the ≤ 1
  LF assertion is UNCHANGED (the same semantics under the new model).
  Separator stability: UNCHANGED — exactly one ╌ footer row at H,
  never duplicated (the wall cannot return: the chrome rows repaint
  over the same row). The 16g idle-hint test: the status row's
  assertion moved from the absolute `\x1b[24;1H` to the relative
  steady-frame write `\x1b[1A\x1b[1G\x1b[0K` (the status sits at H−2
  and the steady frames are relative); at 50 cols the 51-cell status
  now CUTS at W−1 with a … (invariant ① — the old code soft-wrapped
  it; the crash-on-violation makes the cut structural).
- **flood (#13)** — the LF floor (55) and "flood 01 exactly once" are
  UNCHANGED — INVESTIGATED per the auto-green rule: the v6 commit
  model produces the same LF counts by the same mechanism (every
  frozen line commits with exactly one real LF — the measured run:
  ~100 LFs ≥ the 55 floor). "no DECSTBM" unchanged.
- **idle (#14/#15)** — UNCHANGED thresholds — INVESTIGATED: the v6
  zero-timer design makes the idle window structurally silent (no
  heartbeat to beat; the window carries only the post-needle frame
  tail, well under the < 2048 guard). This is the design's
  consequence, not an accidental pass.
- **v2d interleave lint** — the split moved from CUP-only to the
  move/clear sequences (A/B/G/D/K/J — the v6 steady frames carry no
  CUP; the SGRs stay with their lines); the approval question regex
  gained the typed answer (`/^approve .*\(y\/n\) ?.*$/` — the
  ApprovalPrompt slot row).
- **v2b /think** — the `A×100` contiguous assertion became the A-count
  ≥ 100: the /think output is a raw cell, hard-folded at W (invariant
  ①), so the 110-A block arrives as two rows — the CONTENT is all
  there (the fold only hints — the count, not the span).
- **v2c wide-input** — the old cursor-CUP assertions (`\x1b[22;5H`/`7H`)
  are gone with the CUP-free steady frames: the display-width contract
  is now the ROW ITSELF (`\x1b[1m▌ \x1b[0mＡＡ` — the 4-cell pair whole);
  the feeds were split so each typed char's frame is observed (the
  16ms coalescing).
- **v2c submitted-once** — the input row's typed line needs its own
  needle (the frames coalesce — a burst of inserts + the submit lands
  in one frame); the row + the body echo assertions unchanged.
- **v4-reflow ④** — the final screen's `responseOnce` became ≤ 1: the
  content sits at the TOP of the buffer; the shrink's reflow keeps the
  BOTTOM rows (the emulator models the terminal's reflow), so the top
  content scrolls INTO the scrollback — the contract is NEVER a ghost
  (0 = scrolled away, 1 = still visible, 2 = the reflow doubled it —
  the #17 class). The turn snapshot's ①②③ unchanged.
- **v2b/v2e/v2a/modes** — UNCHANGED (content assertions survive).

## New gate surface

- VT-emulator additions: ① the live-cap scalar (H−1) asserted directly;
  ② a super-tall tool output (taller than the whole screen) must
  force-commit — the emulator screen stays coherent, the live count
  never exceeds the cap.
- The five lab scenarios (scratchpad/tui-lab, README documents each):
  1. startup first frame = sequential emission, no pre-clear;
  2. logo rows whole;
  3. no same-row duplicates;
  4. the approval slot takes over the input row and restores;
  5. no concatenated lines.
- The compositor unit tests (packages/tui/tests/compositor.test.ts):
  the two crash invariants, the commit bookkeeping, the force-commit
  edge, the marker cursor derivation, resize idempotence.

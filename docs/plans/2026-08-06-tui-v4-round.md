# TUI v4 defect round (#16, the user's real-machine evidence: dragging the window + the light theme), release 0.1.24

2026-08-06. Spec: "the TUI v4 defect round (#16, the user's real-machine

## Evidence gathering (evidence before code)

- A PTY probe reproduced the resize behavior (the first probe version
  stepped on two pitfalls, recorded: ① NO_COLOR="" keeps the dock from
  ever activating and the resize listener never registers — the root
  cause of the behavior difference between the v2b tests and my own
  probe; ② the old "you> " needle died after #16d removed the prompt).
  The corrected storm probe: after one round completes, 5× TIOCSWINSZ
  (120/60 alternating) at 0.5s intervals, analyzed byte by byte.
- Conclusion one (#16a): the dock's SIGWINCH redraw was already pure
  CUP (zero LF, zero pushes) — the bare-LF count inside the storm
  window is 0. The real defect is **the body's #frozenRows/#oldTailTop
  geometry going stale after a resize**: the next round's new frozen
  lines write to the stale rows (overwriting frozen content or the
  dock) — the root cause of the real-machine "garbage/piling" after
  dragging.
- Conclusion two (#16b): **the raw cell ran escapeTerminal on
  pre-rendered lines at render time**, stripping the banner's dim and
  the recap's blue ▞ ESC sequences and leaving the literals
  "[2m"/"[38;5;75m" — the byte-level proof of the real-machine
  garbage (transcript: `\x1b[19;1H[38;5;75m▞[0m`).
- During the fix another self-introduced regression was found and
  fixed: onResize setting #dirty forced an immediate frame, and the
  tail re-sent the text bytes (the storm gate's "response text exactly
  once" would go red) — changed to only reset the geometry without
  setting dirty; the next natural render takes effect.

## Fixes

- **#16a**: Body.onResize — #frozenRows set to MAX (the frozen area
  counts as full, the next line takes the real-LF scroll path and
  lands above the tail), #oldTailTop zeroed; frozen content is never
  re-sent (the terminal's reflow handles itself), only the dock + the
  active tail redraw. The permanent `tui-v4-storm.test.ts` gate: after
  one round completes, 5× TIOCSWINSZ alternating wide/narrow at 0.5s
  intervals, asserting zero LF during the storm, the separator's
  ANSI-stripped count does not grow, the response text appears exactly
  once in full, no "[2m"/"[0m"/"[38;5" residue, the user block is 7m
  reverse video, the input row is "▌ " (verified on the session
  containing the banner).
- **#16b**: the raw cell passes through (pre-rendered lines keep their
  SGR) — the banner's and recap's garbage disappears at the same root;
  the injection guard stays at the composition point (CLI self-rendered
  content is already escapeTerminal'd at composition).
- **#16c**: the palette's `bg` (the fixed 48;5;237 dark background)
  retires entirely → `rev` (SGR 7 reverse video) — the
  foreground/background swap follows the terminal theme, dark-on-light
  under a light theme; every fixed color audited: blue75/dim/red/green
  are all foregrounds (readable on light), the only fixed background
  was bg — cleared. The design doc synced
  (docs/plans/2026-08-05-tui-v3.md annotated with the v3→v4 changes).
- **#16d**: the input row "▌you> " → "▌ " (the blue brick + the edit
  area); the placeholder hints (queued etc.) stay; the pipe/readline
  "you> " is untouched (v2a line mode byte-for-byte). The PTY
  assertion update list: 23 test files' needles/assertions move from
  "you> " to "▌ " (tui-v2a/b/c/d/e, tui-modes, feel, banner,
  compact-cli, scrollback-flood, idle-probe, kill9, project-trust,
  config-e2e, extensions-e2e, mcp dispose); v2c's edit column math
  updates with the prompt width 6→2 (9/11 → 5/7); the v2d classifier
  and the editor unit tests sync.

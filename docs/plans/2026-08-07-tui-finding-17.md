# TUI finding #17 (P1) — soft lines collapse under terminal reflow; the freeze-as-real-line fix + the resize full clear

2026-08-07. Spec from the user's REAL Terminal.app resize recording:
four symptoms, one root. Two structural fixes, a new probe class (screen
state), zero regression on the existing gates, release 0.1.30.

## The finding (four symptoms, one root)

Recording: a SHORT session (a few frozen cells) drag-resized in
Terminal.app — fold/body lines MERGE (the /think suffix lost), the tail
GHOSTS (the response appears twice), OLD dock separator rows stack into a
wall, and the reflow CUTS out a bare `[`.

Root cause: the pre-fill phase draws every frozen line at an absolute CUP
row (`\x1b[N;1H`) with NO real LF — the content lives in the terminal's
grid as positioned cells, not as real lines. On resize the terminal
reflows the grid: positioned rows reflow as soft lines — they merge,
ghost, and leave residue. The dock + the active tail are the same:
absolute-positioned, never cleared on resize, so the old chrome rows
survive the reflow at their shifted positions (the separator wall, the
tail ghost). The byte probes (LF/CSI counts) are blind to all of this —
the residues never add a newline (structural blind spot).

## Fix 1 — freeze = real line (the pre-fill phase is abolished)

The Body's render() freeze loop stops splitting into a "fits without
scrolling" phase and a "scroll" phase. EVERY frozen line is committed
through the REAL-LF scroll path (`\x1b[${H};1H\n` + write at the body's
bottom row), exactly like the #13 v2d-B overflow path — short sessions
included. Every frozen line is a REAL line in the terminal's stream:
the reflow re-wraps it as one logical line, never merged with a
neighbor. The only soft lines left are the active tail + the dock — both
small and redrawn every frame (or cleared by Fix 2).

The dock keeps repainting after every commit (the classic bottom-bar
method, consistent for the whole session). #15's idle semantics are
untouched: no change, no bytes (the heartbeat still skips a no-change
body).

Consequence (measured on the #16 storm gate, kept): the pre-fill rows
change from top-anchored CUP rows to bottom-anchored scroll rows — the
v2d/v2e/modes/feel/todo gates assert CONTENT only, so they hold; the
storm gate's zero-LF window starts after the last frozen commit, so it
holds; the flood gate's LF floor (55) has slack (75 post-fix).

### The fold must be width-wrapped (a fix-1 necessity)

The thinking fold is NOT wrapped today (up to ~118 cells: 100-char slice
+ "(N chars · /think)"). A soft-wrapped fold at the fixed write row
would overflow into the NEXT row, and the next frozen line's commit
write would CLOBBER that continuation — the /think suffix would be lost
regardless of the reflow (assertion ③ requires it). The fold's slice is
now capped so the whole line fits W: `…<slice> (N chars · /think)` ≤ W.
Decoration stays untouched (out of scope: markdown, colors).

## Fix 2 — resize = full clear + redraw (old geometry, then new)

The Body caches the last-drawn geometry (rows, tailTop). On SIGWINCH:

1. clear the old tail + dock area with the OLD geometry — one ED from
   the last-drawn tailTop (EL/ED only, no LF — the storm gate's
   zero-LF invariant holds);
2. redraw immediately at the NEW geometry (the tail, the cursor home,
   the dock) — the render is idempotent: consecutive resizes clear an
   already-clear area and redraw the same rows.

The #16a assumption is retired: the reflow does NOT erase the old chrome
rows (the recorded wall/ghost prove it) — the clear does.

## The 5th probe class — screen state (a minimal VT screen emulator)

`apps/cli/tests/helpers/vt-screen.ts` (~150 lines TS, a test helper —
NOT counted in the gates): parses CUP/EL/ED/LF/CR only (SGR and any
other CSI skipped), models soft-wrap on overflow, and reflows its
logical lines (LF-delimited) at a new width on resize. The PTY byte
stream feeds the emulator; the driver records each TIOCSWINSZ's byte
offset and the test applies `emulator.resize(rows, cols)` at those
offsets, so the emulator's geometry tracks the process's.

The new gate (real PTY, a slow extension tool keeps the tail LIVE across
the 5-resize sequence — tall/short/wide/narrow alternating): asserts on
the emulated screen:
- ① the response text appears exactly once (the tail ghost);
- ② separator (╌) rows in the BODY region ≤ 1 (the old dock rows that
  the reflow left in the body area — the wall; the dock's own two ╌
  rows sit at H-3/H-1, outside the region);
- ③ the fold is its own logical line ENDING with "/think" (the merge +
  the suffix);
- ④ after the resize sequence, ① and ② re-run on the final screen;
- ⑤ no row is a lone "[" (the reflow cut).

The existing byte probes (LF/CSI counts) are ALL kept — this probe
complements them: it sees what the byte counts cannot (the screen
state).

## 1. Diff computation (diff.ts, ~150 src, zero dependencies)

- edit_file: the search→replace window replaces IN PLACE (the changed
  region is known — no general engine), LCS over the old vs new file.
- write_file: a row-level LCS against the old content (small files are
  the target); a NEW file is all +.
- 2 context rows per side; >40 lines truncate to 18 head + 18 tail +
  "… N lines (/last for full)" (the stats come from the FULL diff —
  the truncated view never corrupts +N -M).

## 2. Presentation (the core ruling)

- **At the approval**: the mini-diff renders BELOW the tool line — ▎
  blue edge (the brick motif), - red / + green / context dim; NO_COLOR
  keeps plain ± prefixes. The human sees the change before deciding —
  the round's value proposition.
- **After the approval**: the frozen summary stays ONE line
  "✓ edit_file (…, +1 -1, 1.2s)" — the diff does NOT freeze (v2d's
  anti-leak principle unbroken); /last has the full data.
- Auto-allowed tools (policy allow) skip the diff; pipes/non-TTY render
  nothing (the passthrough is unchanged — the pipe diff vs the v2c
  baseline stays EMPTY).

## Part 2 — TUI v2b

### 3. Content strategy (user-recording spec)

- **Thinking folds** to ONE dim line per block — first 100 chars +
  ` (… /think shows full)`; the block's newline closes it. The consumer
  buffers the block's deltas (`flushThinking`) and folds once at the
  block's end — the 自举 P1 one-segment property survives (test:
  `render-safety` "the fold renders the WHOLE block on one line").
- **`/think`** prints the last complete thinking block straight from the
  event stream (the /last pattern); `[no thinking yet]` before any.
- **`[result]` echoes truncate at 160 chars** + ` (/last for full)`;
  the ✓/✗ summary line is unchanged; body text deltas stream in FULL.
- **Pipes and non-TTY get the same content strategy** — the pipe-mode
  byte diff vs v2a baselines shows EXACTLY the declared differences
  (`/tmp/kiso-v2a-after-{one,two}-turns.txt` vs the v2b regen: only the
  `[result]` truncation differs; short thinking blocks render
  byte-identical).

### 4. Bottom-anchored UI (TTY only, ~370 new lines, zero dependencies)

- **DECSTBM scroll region** rows 1..H-3 on enter; bottom rows H-2/H-1/H =
  dim separator / live status bar / blue `you>` input line.
- **Live status bar**: session id · model · [turn N · faux] · in/out/cache
  tokens · ctx ~%; a running tool appends `running <tool> Ns`; the
  spinner glyph merges into the bar (no more standalone spinner line).
  Unknowns omitted (v2a denoise rule).
- **Approval/uncertainty/trust questions take over the status position**
  (question at H-1, answer at the input line), restored after the answer.
- **SIGWINCH** re-applies the region and redraws the chrome;
  teardown (`exit` / signal / exception) resets with `\x1b[r` in a
  finally — kill -9 excepted (README: `reset` saves it).
- **Bottom redraws wrapped in CSI 2026** synchronized output — the pi
  anti-flicker trick as an escape sequence, not a library.
- Pipes / NO_COLOR / a TTY with rows < 4 → the dock never activates; the
  v2a line mode stays byte-for-byte (existing e2e guards it).

### 7. Findings during the round

- **Two failing PTY tests were test-driver bugs, not CLI bugs.** (a) The
  approval test's feed needle `"you> "` matched the FIRST prompt, so
  `exit` was typed at startup → `rl.close()` mid-turn → the approval's
  `rl.question` threw `readline was closed` (probe-confirmed Node
  behavior) → `[run failed]`. Fix: trailing feeds key on `turn 2 · faux`
  (the turn's terminal event) — collision-free. (b) The SIGWINCH test
  sent `exit` and the winch in the same 0.2s poll — `exit` won, the dock
  teardown removed the resize handler before the signal landed. Fix: the
  driver types `exit` on a timer 0.5s AFTER the winch. Diagnosis chain:
  SIGUSR1/SIGWINCH dead in pty children → forkpty-vs-fork isolation →
  marker-file ground truth (signals DO arrive) → matrix (stdout resize
  fires with readline) → the CLI's own markers (`[dock-enter]` fires,
  `[proc-SIGWINCH]` silent) → fixed-delay winch at the idle prompt:
  EVERYTHING fires, `\x1b[1;27r` written. The CLI was never broken; the
  driver raced it.
- **The `[result]` truncation also applies in pipe mode** — the diff
  above pins it; `(/last for full)` is the pipe user's recovery path.
- **Pre-existing edge, not fixed this round**: `exit` typed at the
  prompt while a turn is in flight closes the readline mid-run; a later
  approval then fails loudly with `readline was closed` (v2a behavior,
  unchanged).

## 11. Follow-up fixes (real-machine report + P3 审查, no separate release)

The user's real-machine report after installing kiso-code 0.1.13: typing
drifts at the input line, and the sent text is invisible after Enter.
Plus the P3 审查 finding: dock.ts emitted `\x1b[2026h/l` — the DEC
private-mode prefix "?" was missing (correct: `\x1b[?2026h/l`, the pi
source's form); terminals silently ignore the bare form, so the
anti-flicker never engaged (cosmetic only).

Three fixes (commits 1ade829, d7b2702, 6a7ccc8):

1. **P3**: both synchronized-output sequences carry the "?" prefix. A PTY
   byte assertion now pins `\x1b[?2026h` (and the bare form's absence) —
   the gap the three-terminal transcripts could not close.
2. **Cursor drift**: the body write's cursor return went to column 1;
   readline tracks its cursor internally and NEVER re-syncs after an
   external move (probe-confirmed) — the next keystroke overwrote the
   prompt and self-repaired ~200ms later on the next redraw, read as
   drift. The dock now has ONE cursor home — the input line's edit
   position (prompt width + cursor + 1) — for redraws and body returns.
   The docked ask() also reads at the same blue `you>` prompt (an empty
   question prompt made readline start at column 1 while the dock
   rendered "you> ").
3. **Sent line invisible**: the double-echo filter assumed readline's
   echo and the body share one scrollback (v2a line mode). In the dock
   the echo lives in the input row, which the next redraw clears — the
   body render is the only visible copy. The filter now skips only when
   NOT docked; the sent line renders blue into the body. Pipes and v2a
   line mode keep the old filter byte-for-byte.

Verification: full suite 471 green (the v2b test 1 now also asserts the
sent-line body render `\x1b[38;5;75myou> look around\x1b[0m\r\n\x1b[24;6H` —
the edit-position return pinned); tmux real-machine re-check shows
`you> look around` as the first body line and a clean exit. No release
per the instruction — rides with the next round.

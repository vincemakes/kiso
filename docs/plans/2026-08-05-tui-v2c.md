# TUI v2c — the dock draws its own input line

> Date: 2026-08-05
> Status: complete — spec sections 1-8 delivered, acceptance gate green
> Authority: direction ruling 2026-08-05 (user): the TUI v2c spec. The
> design ruling: borrow pi-tui's mechanism, not its code or dependencies;
> the visual identity is the kiso brick motif (ADR-0039 Amendment 2).
> cli gate 1600 (1544/1600 at completion — the editor is +~390 over v2b,
> within the ~+350 budget's spirit; 56 lines of headroom).

## 1. Root cause (recorded per the spec)

v2b's readline + DECSTBM coexistence is a STRUCTURAL conflict: readline's
redraw assumes it owns the row exclusively and positions by character
count — a CJK wide character (2 cells) shifts every following column, and
the dock's redraws make the mismatch permanent. Probe-confirmed: readline
NEVER re-syncs its tracked cursor after an external move (the next
keystroke lands at the ACTUAL cursor, overwriting the prompt). Patching
is a dead end; the TTY path switches to a raw-mode self-drawn editor;
non-TTY keeps readline (pipe bytes unchanged — the v2b diff is EMPTY).

## 2. The minimal editor (zero dependencies, editor.ts)

- **eastAsianWidth subset** (~40 lines): CJK unified/ext, kana, hangul,
  fullwidth forms, CJK punctuation, emoji ranges = 2; everything else 1.
  Cursor positioning AND horizontal scrolling are display-width based —
  Chinese input not drifting is the hard acceptance (PTY e2e: 你好 lands
  at columns 9 then 11 — 6-wide prompt + 2 per char — never 7/8).
  Known limitation (README): emoji ZWJ clusters are not perfect.
- **Key set**: UTF-8 printable (TextDecoder stream, multi-byte safe),
  Enter, Backspace (0x7f/0x08), Delete (CSI 3~), ←→ (CSI D/C),
  Home/End (CSI H/F) + Ctrl+A/E, Ctrl+U/K/W, Ctrl+C/D, bare Esc.
- **Bracketed paste**: ?2004h on enter, unwrap 200~/201~, internal
  newlines → spaces (single-line editor), ?2004l on teardown.
- **Over-wide input**: width-based horizontal scroll, dim "…" at the
  line head.
- **Startup submits queue** (never dropped — the rl-in-main race) and
  the readline path buffers 'line' events the same way.

## 3. Symptom fixes

- **Sent-visible (symptom 2)**: the user_input event renders into the
  scroll region exactly once (PTY e2e pins the exact-once byte shape);
  the editor's row is not the body, so there is no double.
- **Input not swallowed (symptom 4)**: keys during a run go into the
  live editor buffer; Enter enqueues on the chain (existing semantics)
  and the status bar shows "+N queued" (PTY e2e: two lines typed at
  once — "+1 queued" appears and the second turn executes).
- **Contrast (symptom 3)**: user echo blue; assistant body default;
  thinking fold/[result]/separator dim; status bar dim with blue
  accents; the separator is the dotted ╌.
- **Cursor (symptom 1)**: cured by the width math; PTY e2e asserts the
  Chinese cursor columns.
- **Esc** aborts a paused run (equivalent to Ctrl+C's run branch);
  Ctrl+C on an empty line exits, on a non-empty line clears; Ctrl+D
  exits on an empty line.

## 4. Visual identity (kiso brick motif)

The input row opens with a blue half-block ▌ (echoing the pixel logo)
then blue you>; the upper separator is the dim dotted ╌; below it the
live status bar. Deliberately not the CC rounded frame, not the pi
editor (ADR-0039 Amendment 2).

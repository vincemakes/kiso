## 2. Finding #12 (P2) — the failed-receipt uncertain pause, removed

Diagnosis (from the event flow, per the spec — no presumption):
`executeOne` writes the failed receipt with `safeToRetry: tool.idempotent
=== true` and delivers the ✗ result; the caller's C group block then finds
the receipt and pauses for `!safeToRetry` — and the MCP bridge maps tools
WITHOUT declaring idempotency, so every MCP failure (even a read-only
directory_tree ENOENT) hit the pause. The rule was deliberate AND tested
(execution.test.ts "a failed NON-idempotent execution PAUSES as
uncertain") — per the spec's stop-and-report clause the diagnosis was
reported and the user ruled (ruling #12, option A + amendments 1/2):

- the C group failed-receipt pause is removed from BOTH the live loop
  (kernel/loop.ts) and its redundant twin in the recovery executor
  (runtime session.ts `#executePersisted`) — a complete receipt IS the
  outcome; `uncertainExecutions()` reports the crash window alone; the
  ledger's status derivation follows (failed → "failed", never
  "uncertain"; safeToRetry stays on the event for history);
- amendment 1: a non-idempotent failure's result carries the honest note
  `[non-idempotent tool failed — its side effects may have partially
  applied; verify before retrying]` — live and recovery paths
  identically, receipt and tool_result losslessly; idempotent failures
  carry no note; the MCP bridge keeps not declaring idempotency
  (unknown = the note applies);
- amendment 2: the CLI's ⚠ line is pure information on old-log replays;
  the (r)erun/(a)bandon question now belongs to the crash window's
  recovery flow alone.

Red → green: the rewritten C group tests failed against the old code
(uncertain_pending present, no note); the CLI e2e (approved→failed(fatal)
→ zero uncertainty questions, note rides the result) was red on the old
build; green after. Crash window zero regression: the kill -9 gate, the
offline resolveUncertain shapes (uncertainty-flow, adversarial-race,
execution-id), all green. 466/466, `npm run check` EXIT 0.

## 1. Architecture (hard)

- **The ONE writer**: `body.ts`'s render loop is the only code that
  writes the scroll region; every event handler mutates a cell —
  interleaving is impossible by construction (the round's acceptance
  core, pinned by the lint e2e).
- **The cell model** (ours, not pi's Component shape — ADR-0040):
  UserCell / ThinkingCell / ToolCell / TextCell / NoticeCell / raw /
  terminal.
- **Freeze semantics**: completed cells print once and are never touched;
  the ACTIVE TAIL (unfinished cells) renders at the region's bottom and
  redraws in place (CSI 2026, the v2c cursor math). An over-height tail
  overflows to freeze by completion order.
- **Frame scheduling**: ≥16ms coalescing + a 200ms heartbeat (spinners /
  elapsed).

## 2. ToolCell lifecycle (the leak cure)

One line: `→ name summary` (≤60 chars) → ⏸ badge at an approval pause →
running (blue spinner + Ns) → frozen `✓ name (summary, 1.2s)` /
`✗ name (first error line, 1.2s)`. The [result] no longer flows (the
body holds the full data for /last); parallel tools each own a cell.

## 10. #13 (P1) rework — the body renderer had no scroll-out mechanism, fixed via the B route

**Finding #13**: a frozen cell is written by absolute positioning into
the scroll region's bottom row; on overflow the DECSTBM region scrolls
internally — on a real terminal (the Terminal.app family) rows scrolled
inside the region **never enter the native scrollback**, and old content
is overwritten in place (user-measured: LF=2 / CSI-S=0 / ESC-D=0 / old
content visibly overwritten), violating v2d's core clause "frozen lines
print into the scroll region, native scrolling is preserved".

**Route chosen (B)**: the classic DECSTBM bottom-dock route is abandoned.
The body has no margins — frozen content prints with REAL LF (the
terminal scrolls naturally, the scrollback is preserved natively); until
the screen is full, absolute positioning fills from the top (no
scrolling); after it is full, each line is `\x1b[H;1H\n` (real LF, the
whole screen scrolls, the top line enters the scrollback) + the body's
bottom line is written (above the tail); after every landing the dock is
redrawn. Cost = a slight increase in repaint traffic (the dock redraws
per frame), in exchange for deterministic scrollback correctness — not
relying on the terminal's region-scrolling temperament (the spec's ⚠
had warned).

**Two collateral defects found during implementation** (reproduced by
probes and fixed):
1. the runtime never emits `text_end` (an adapter-layer event) — the
   text cell never closes, freeze is blocked, and the subsequent done
   cells all pile up in the tail being redrawn repeatedly by the
   heartbeat (the flood probe reproduced "flood 01 ×38"). Fix: opening
   a new cell closes the open text cell (the same pattern as
   closeOpenThinking).
2. the tail was sliced before freezing — a stale tail painted
   already-frozen cells again ("flood 01 ×2"). Fix: compute the final
   nextFrozen/tail geometry first, then freeze, then paint the correct
   tail.

**Acceptance**:
